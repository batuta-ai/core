## Decisions and context

The renderer is `loop/panel_render.go` (`Render`, `panelRenderer` with `attention`, `detail`, `progress`, `row`, `tableRow`, `box`, `fit`, `colour`). Today colour is a token pass over finished lines (`colour`, line 455): it paints glyphs only and knows nothing about rows. This plan replaces it: lines are built from `segment{text string; kind paintKind}` slices, each line has a `lineKind`, `fit` and `panelWidth` operate on the concatenation of the plain texts, and `paint` emits SGR around each segment (`\x1b[<codes>m` … `\x1b[0m`) and around the whole line for the line kind, after fitting, so column arithmetic never sees escape codes. One table `paintTable map[paintKind]string` holds the codes (for example `selected: "7"`, `selectedUnfocused: "2;7"`, `stateIntegrated: "32"`, `stateRunning: "34"`, `stateBlocked: "1;31"`, `stateWaiting: "1;33"`, `statePending: "2"`, `waveActive: "1;34"`, `wave: "1"`, `dim: "2"`, `chip: "7"`, `logProgress: "1;36"`, `logError: "31"`, `logPrompt: "1"`, `barDone: "32"`, `barRunning: "34"`, `barEasing: "94"`, `focusBorder: "34"`). ANSI 16 plus bold, dim and reverse only: no 256-colour, no truecolour, no lipgloss; the terminal theme keeps the contrast. `style.Colour` already comes from `StyleForWriter` (`NO_COLOR`, TTY): keep that gate and remove the second `os.Getenv("NO_COLOR")` check in `Render`. With colour off the output must be byte-identical to today, which every golden proves.

Executors run in a codex sandbox without a terminal: never open a pty in tests; build the strings and compare. Every Go command in the sandbox is prefixed with `HOME=/private/tmp/batuta-home GOCACHE=/private/tmp/batuta-gocache GOPATH=/Volumes/Home/francisross/go GOMODCACHE=/Volumes/Home/francisross/go/pkg/mod GOFLAGS=-mod=mod GOPROXY=off`; `GOTOOLCHAIN` stays `auto`. Do not edit `go.mod` or `go.sum`, do not run `go mod tidy`. Environment setup is never a question: apply the recipe and continue.

**Task 1.** The selected task is `model.Detail.Task` (the model already resolves the selection to the active task when nothing is selected); `style.Focus` is `"table"`, `"log"` or empty. The marker `▶` replaces the first character of the ID cell's left padding so the column widths do not move (the ID column is 7 wide; the row today starts with a space). State names in the model are the journal's (`integrated`, `running`, `executor`, `blocked`, `failed`, `waiting_input`, `pending`, `candidate`, `preparing`, `conflict`): map them to the five paint states in one function next to `stateGlyph`. The active wave is the one whose state is running (`>`); `before run` is the synthetic wave whose state is `before_run`. The header's right side already carries the state word: paint it with the state colour too.

**Task 2.** The bar geometry is fixed (24 cells, `█`/`░`, or `#`/`.` in ascii); paint the run of filled cells as one segment and the single cell whose value is between the shown float and the next integer as `barEasing`. The focused box is `style.Focus` (`table` → the waves box, `log` → the log box); when `style.Focus` is empty no border is painted blue and all borders are dim. Key chips: the key line is built from `labels["keys"]`/`labels["keys_focus"]` as `key description · key description`; split on ` · `, then on the first space, to paint the key as a chip. Log classification runs on the plain line before painting; `$ ` marks a shell command echoed by the executor.

**Task 3.** Colour goldens are produced once by the test itself when the file is missing (`-update` flag pattern is fine: `go test ./loop -run TestRenderMatchesColourGoldens -update` writes them) and committed; from then on they are compared byte for byte. Pick the fixtures of `TestRenderMatchesGoldens` for calm and question, width 120, English, Unicode, `Colour: true`, `Focus: "table"`, selection on the active task, `Frame: -1`. The legend lives in `panelLegend` in `loop/panel_keys.go` (in scope, with its test): add the colour lines there, texts from `loop/panel_labels.go` in both languages.
