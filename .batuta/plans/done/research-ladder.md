## Decisions and context

The skills repository fixes the table format first (`skills/.batuta/plans/research-ladder.md`): the Role table becomes `| Role | Lane | Executor | Model | Cost |`; `review` keeps one row with `—` in the Lane cell; `research` has one row per seated lane, `low` mandatory when research exists, `medium` recommended, `high` optional. A Role table without a `Lane` column stays valid and means research `low`. Every research row names a CLI executor (never `self`) and an exact model, exactly like the review role's validation. Go standard library only, frozen exported signatures except the additions named here, conventional commits, no journal schema change.

Today `parseReviewRole` in `routing/table.go` skips every role except `review`, so research rows are invisible to the core and absent from `RoutingTable.Digest`. The loop's `verify` in `loop/attempt.go` seats the independent read-only verifier on the implementation `low` row of the task's domain when that executor differs from the writer, else on the task's own adapter and model. A `high` task is therefore verified by the cheapest coding model. Research is the doctrinal home of read-only work; seating the verifier there by lane is the point of this plan.

**Task 1.** Add `Research []RoutingRow` to `RoutingTable` (Domain is always `*` for research; keep `Line`). Generalize the role-table scanner so one pass yields the review role and the research rows: header lookup by name as today, `lane` optional; a research row with an empty or `—` Lane cell is `low`. Validation mirrors `parseReviewRole`: executor matches `tableExecutorPattern` and is not `self`; model is exact (no empty, `—`, `<placeholder>` or `default`); a second research row for the same lane is a duplicate error naming both lines; an unknown lane word is an error. Include research rows in the digest after the review part, in lane order, as `"research"`, lane, executor, model. Add `func (t RoutingTable) ResearchRow(lane Complexity) (RoutingRow, bool)`: exact lane, else the nearest lower seated lane walking `complexityLadder` down, else false. Extend `TestParseRoutingTableReviewRole` fixtures rather than duplicating them where a shared fixture reads better.

**Task 2.** In `verify`, the seat order becomes: the research row for the task's lane, then each lower research row, taking the first whose executor differs from the writer's adapter name and whose adapter loads through `adapterLocked`; when none applies, keep the existing rule unchanged (implementation `low` row of the task's domain if it differs from the writer, else the task's own adapter and model). Do not change the prompt, the guard, the dispatch detail schema or the ACP verifier path; the existing `Executor` and `Model` fields already record the seat. Tests use the existing fake adapters and routing fixtures in `loop/attempt_test.go`; the new tests assert on the recorded verifier dispatch executor and model. Update the "Verifier" bullet in `docs/loop.md` to state the seat order in one sentence.
