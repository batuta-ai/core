**Goal:** Close items 4.6 and 4.1(b) of `.batuta/feedback/2026-09-21-tempo-mvp-triage.md`. `batuta review` never writes `null` findings, records why coverage is incomplete as structured review failures, and exits 4 for an incomplete review so exit 3 means product defects only. ## Decisions and context

Go standard library only, conventional commits, table-driven tests with `t.Parallel()`, temp dirs through `tempDir(t)`. `cmd/batuta` must build on linux, darwin and windows. Every CLI form prints compact JSON or TSV. Source of the requirements: `.batuta/feedback/2026-09-21-tempo-mvp-triage.md` rows 4.6 and 4.1. Release tooling (`CHANGELOG.md`, `.release-please-manifest.json`, `release-please-config.json`, `.goreleaser.yaml`, `.github/workflows/*`) is never touched.

Environment setup is never a question. For Go inside a sandbox on this machine: `HOME=/private/tmp/batuta-home GOCACHE=/private/tmp/batuta-gocache GOPATH=/Volumes/Home/francisross/go GOMODCACHE=/Volumes/Home/francisross/go/pkg/mod`, `GOTOOLCHAIN` stays `auto`. Run the tests named in your task's Accept lines. If the sandbox blocks the Go build cache or a loopback listener, write the tests and say so in the report: the conductor's gate runs the whole suite.

Decided with the maintainer on 2026-10-05: the loop probes once per route per delivery (not every attempt); `batuta dispatch` probes only with `--preflight`. A route is executor, model, effort and transport together.

Decided while planning, open to change at approval: `findings.json` stays a JSON list of findings so existing readers keep working, and the review failures go to a fifth artifact `review_failures.json` instead of into `findings.json`. The last line of `review.md` stays exactly `Verdict: <verdict>` because the loop's supervision parses it with `^Verdict: (SHIP|FIX_BEFORE_SHIP|REWORK)\n?\z` (`loop/supervision_review.go` ~447); the reason goes into a `Review failures:` section above it, not into the verdict line the triage sketched.

**Tasks 1–3.** `BuildReport` (`review/report.go` ~30) merges the cohorts' findings with `var findings []Finding` and forces `Rework` when any cohort is uncovered, a cohort's lint failed or the spec sweep is uncovered; `WriteArtifacts` (~160–185) writes `manifest.json`, `findings.json`, `review.md` and `state.json`, and the artifact list also appears in the cleanup around ~310. `CohortResult` (`review/session.go` ~116) carries `Covered`, `Reason` and `Attempts []SessionAttempt`. `runReview` (`cmd/batuta/main.go` ~1015, exit mapping ~1212) maps SHIP → 0, FIX_BEFORE_SHIP → 2, anything else → 3. The loop's supervision reads the four artifacts in `loop/supervision_review.go` (~401 and ~436) and sets `incomplete_coverage` (~473) from the text of `review.md`; review directories written by older binaries exist on disk and must still load.

**Tasks 4–6.** Dispatch lives in `executor/dispatch.go` (`Dispatch`, exit classes 0 completed, 1 failed, 2 unavailable or invalid_arguments, 3 waiting_input, 4 rate_limited, 5 uncertain; 124 and 130 for timeout and interrupt); 6 is free. The loop's attempt is `runAttempt` (`loop/attempt.go` ~175); failures go through `recordFailureWithPolicy` (~883), whose conducting policy retries once on the same runtime and then escalates one row, writing the trail verdict `⏫ escalated from …` (~944). Journal records go through `Runner.record` (`loop/runner.go` ~942). The probe exists because a headless executor that can edit files but cannot run commands parked whole deliveries in `waiting_input` on the Tempo run; the probe brief stays one paragraph and never mentions the task.

After the plan, outside it: the `batuta-review` skill in `batuta-ai/skills` documents exit 4 and `review_failures.json`; the host pins the release that carries this plan. The rest of the triage (`--recover`, worktree isolation and cleanup, grants, the skills items, `trail --metrics`) gets its own plans.
