**Task 1.** Findings to close, verbatim from the review:
- [5] blocker · loop/attempt.go:714 · premise: snapshotWorktree treats an empty SHA from Park as successful preservation. However, worktree.GitProvider.Park returns an empty SHA when no parked ref exists and the working tree equals its current HEAD, even when HEAD contains unmerged executor commits. · path: An executor commits its changes and subsequently fails. Failure recording calls snapshotWorktree, which creates no recovery ref for this clean worktree. When the failure policy blocks or escalates, recordFailureWithPolicy removes the worktree and force-deletes its branch. · verdict: Unmerged committed work loses its protecting ref and is absent from the recovery summary; Git garbage collection can permanently delete it. · fix: Before accepting an empty snapshot result, ensure unmerged HEAD is protected by a parked ref. Adjust Park to distinguish equality with an existing recovery ref from equality with an unprotected HEAD, and add a regression covering clean committed work followed by blocking cleanup.
- [9] blocker · worktree/git.go:234 · premise: When no parked ref exists, Park compares the snapshot tree against the worktree HEAD and returns success without creating a ref if they match. · path: An executor commits its changes and then fails verification. The failure handler calls snapshotWorktree on the clean worktree; Park returns an empty SHA. On escalation or abort, GitProvider.Remove deletes both the worktree and its branch. · verdict: Committed executor work loses its recovery ref and becomes eligible for garbage collection, despite parking reporting success. · fix: Skip snapshot creation only when an existing parked ref already preserves the tree, or when preservation in integration history is proven. Otherwise create the recovery ref even for a clean worktree. Add a committed-work cleanup regression test.

`Park` is in `worktree/git.go` (~line 234): the equality shortcut must compare against an existing parked ref's tree or prove reachability from the integration branch (`git merge-base --is-ancestor HEAD <integration>`), never against the worktree's own HEAD. `snapshotWorktree` in `loop/attempt.go` (~line 714) must fail closed: an empty sha with unmerged commits is an error that stops the cleanup, not a success. The summary printer is in `loop/report.go`.
