# Plan — Worktrees outside the repository and orphan worktree cleanup
<!-- inputs: profile.md@sha256:e18a00765937 routing.md@sha256:bdb31fda5c7d -->

**Goal:** A project can keep the loop's task worktrees outside its repository, so test runners and linters that scan dot-directories never see them. The conductor can list and remove batuta worktrees that no open delivery owns. This is the core half of finding 4.4 of the Tempo retrospective (`.batuta/feedback/2026-09-21-tempo-mvp-triage.md`).

## Decisions and context

Finding 4.4 has three parts. This plan covers two of them in core: (b) worktrees outside the repository and (c) removal of orphaned worktrees. Part (a), where `batuta-init` adds `.batuta/**` to the ignore lists of vitest, eslint, tsconfig, jest and pytest and writes `Worktree-home: cache` for JavaScript and TypeScript stacks, belongs to batuta-ai/skills and gets its own plan after this one ships. Killing processes whose working directory is inside a removed worktree is not in this plan: it needs per-OS code with no standard-library support on macOS and Windows, and it gets its own plan.

The default stays `repository`, so no existing project changes behaviour. The profile line is `Worktree-home:`, not a value of the existing `Worktree:` line: `Worktree:` is read by the interactive skill as `off | medium+ | always` and core only stores it.

The two homes are the repository home `<root>/.batuta/worktrees` and the cache home `<os.UserCacheDir()>/batuta/worktrees/<digest>`. `os.UserCacheDir()` is `~/Library/Caches` on macOS, `$XDG_CACHE_HOME` or `~/.cache` on Linux and `%LocalAppData%` on Windows. Tests set `HOME`, `XDG_CACHE_HOME` and `LocalAppData` to a temp dir through `t.Setenv`; a test that calls `t.Setenv` cannot call `t.Parallel()`. Temp dirs come from `tempDir(t)`, which resolves symlinks on macOS.

The runner names a worktree `<slug>-task-<N>-e<K>` (`Runner.worktreeName`) and its branch `batuta/<slug>/task-<N>-e<K>` (`Runner.branchName`).

The repository conventions apply to every task: standard library only; `cmd/batuta` builds on linux, darwin and windows, so no bare `syscall`; every CLI subcommand prints compact JSON or TSV and exits 0 on pass, 2 on fail, 1 on error; the public signatures `NewArtifactLoader`, `BuildCandidateBindings`, `Selector.Select`, `RecordFailure` and `SettleWave` stay frozen.

**Task 1.** `Home` is a new exported field of `GitProvider`; an empty `Home` means the repository home, so every existing caller keeps its behaviour. `Add` creates the home with `os.MkdirAll` and mode `0o755`. `Path` does not touch the disk. `Dir` and `Excluded` stay as they are. `RepositoryHome(root)` is the one place that joins `root` and `Dir`; `Path` uses it. The canonical root is `filepath.Abs`, then `filepath.EvalSymlinks`, then `filepath.Clean`; `CacheHome` returns the error of `EvalSymlinks` for a root that does not exist. The digest is taken over the canonical path as it is, with no case folding: two spellings that differ only in case on a case-insensitive file system may give two homes, and `EvalSymlinks` already returns the on-disk spelling on macOS.

**Task 2.** `profileLine` in `loop/profile.go` is the regular expression that names the accepted lines; add `Worktree-home` there. `ParseProfile` returns no error today and `LoadProfile` does; validate in `LoadProfile` and keep the signature of `ParseProfile`.

**Task 3.** A `GitProvider` is constructed in four places: `loop/runner.go` (`worktree.New`, the runner and everything built on `prepare`: `Recover`, `Abandon`, answer, resume), `loop/reconcile.go`, `loop/roadmap.go` and `cmd/batuta/gate.go`. Only the runner creates worktrees. The other three read refs, the registry or a directory they are given, so they keep the default `Home`. The runner sets `git.Home` from `worktree.CacheHome(root)` when the profile says `cache`. Two places build a worktree path by hand: `ensureWorktree` in `loop/attempt.go` (the `snapshotWorktree` call) and `previewTask` in `loop/runner.go` (`worktree.Dir`); both go through `GitProvider.Path`. As of this plan only `loop/attempt.go`, `loop/runner.go` and `loop/claims.go` hold the literal or read `worktree.Dir`; `loop/reconcile.go`, `loop/roadmap.go` and `cmd/batuta/gate.go` do not. `TestNoHandBuiltWorktreePath` lives in `loop/loop_test.go`. It reads the non-test `.go` files of `loop/` and `cmd/batuta/` from disk and fails on a match; `loop/claims.go` is covered by task 5, so until then the test may exempt that one file by name, and task 5 removes the exemption.

**Task 4.** `ensureWorktree` in `loop/attempt.go` prefers the journaled `WorktreeRoot` when the directory exists; when it is gone, the code falls through to a new worktree in the provider's current home. The fix recreates it at the journaled root through `GitProvider.AddAt(ctx, path, branch, baseSHA)`, which does what `Add` does for an explicit absolute, clean path. An attempt with no journaled root still uses `Add`. `AddAt` takes the allowed homes as an argument and refuses a path whose parent is none of them, so a corrupt journal cannot place a worktree elsewhere; the caller passes `worktree.RepositoryHome(root)` and `worktree.CacheHome(root)`. `Recover` and `Abandon` rebuild the runner's worktree map from journal records (`loop/report.go`, `loop/settle.go`, `loop/recover.go`), so they should already follow the journal; the two profile-change tests prove it, and those files are in Scope for the case where one of them computes a path from the provider instead.

**Task 5.** `markdownLinkPath` in `loop/claims.go` finds the worktree by the constant `claimWorktreeMarker` (`/.batuta/worktrees/`). The cache layout has no such marker, so the extraction needs the resolved home of the delivery as an input. `ExtractClaims` has three callers: `claimEvidence` code in `loop/judgment.go` (the live path, through `ClaimEvidenceInput`) and the replay and corpus commands in `cmd/batuta/judge.go` and `cmd/batuta/judge_corpus.go`. Carry the home through `ClaimEvidenceInput` and `ReplayClaimEvidenceInput`; the variadic `known` parameter of `ExtractClaims` must keep working for existing callers. Match the exact home prefix followed by one worktree name segment, never a substring. Compare in slash form: a home given as `C:\Users\x\AppData\Local\batuta\worktrees\<digest>` matches the target `file:///C:/Users/x/AppData/Local/batuta/worktrees/<digest>/<name>/<path>`. The repository home keeps working without a home input. `claimWorktreeMarker` holds the text `/.batuta/worktrees/`, which contains the literal the test of task 3 looks for. Either build the marker from `worktree.Dir`-free helpers so the exemption goes away, or keep the constant and keep a named exemption with the reason in a comment.

**Task 6.** The ownership rule has three parts, all required. First, the parent directory of the worktree path equals one of the `homes`, both sides canonicalised the same way: `filepath.EvalSymlinks`, and when that fails because the directory does not exist, `filepath.Clean` of the absolute path. A deleted home therefore still matches its registered worktrees, which come back with `Missing` set. Second, the branch matches `^batuta/(.+)/task-([0-9]+)-e([0-9]+)$`, the slug being the greedy first group. Third, the directory name equals `<slug>-task-<N>-e<K>` built from those groups. A worktree that fails any part is not managed and is never returned. Read the registry with `git worktree list --porcelain -z` and split on NUL, as `nulFields` does for `MergePreview`. A detached entry has no `branch` field and is left out. An entry git marks `prunable`, or whose directory fails `os.Lstat`, is returned with `Missing` set when its branch and recorded path pass the rule. The runner bounds git output at 16 MiB; `StdoutTruncated` is an error, and the test uses a fake runner like `truncatingRunner` in `worktree/git_test.go`.

**Tasks 7–8.** A delivery is closed only when its journal ends in `done` or `abandoned`. Every other delivery is open: one with no terminal record, and one that ends in `waiting_input`, `waiting_plan`, `blocked` or `canceled`. The terminal states are the `State*` constants in `loop/runner.go`; `review_blocked` is a supervision gate state of a `done` delivery, not a terminal state, so such a delivery is closed. An open delivery owns the worktrees its journal names: match on the recorded `worktree_root` and on the branch built from the delivery's slug, task and execution, never on the slug alone. A managed worktree that no open delivery owns is an `orphan`, or `missing` when `Managed` sets `Missing`; this includes a worktree that `--keep-worktrees` left after a finished delivery and a worktree whose slug has no journal. `openDeliveries` in `loop/report.go` is not a model: it skips journals it cannot read and uses a different rule. `journal.Store.List` is not strict either: it skips an entry whose `entry.Info` fails. `Prune` scans the journal directory with its own strict listing in `loop/prune.go`, behind a small unexported function variable that the tests replace to inject each failure. `Prune` fails closed: an error from listing the journal store, from reading one journal, or from a journal whose first record is not a valid opening stops it before any report line and before any removal.

**Task 7.** `Prune` builds both homes itself (`worktree.RepositoryHome(root)` and `worktree.CacheHome(root)`), whatever the profile says, so worktrees of an earlier profile setting are found. The report takes no lock. A live presence lock is one that `liveDeliveryOwner` in `loop/presence.go` reports as live; `presenceFiles` lists the lock files of a workspace.

**Task 8.** There is no repository-wide lock, and this plan adds none. `Apply` first refuses while any presence lock of the workspace is live. Then, immediately before each removal, it reads the journals and the git registry again and removes the worktree only if it is still a managed orphan with the same path and branch; otherwise the entry becomes `skipped`. The guarantee that nothing is removed on a journal error covers the first scan only: an error at a later re-read stops every further removal, and `Prune` returns the entries processed so far with the error. `GitProvider.Remove` runs `git worktree prune`, which drops the stale registration of every `missing` entry of the repository; that is accepted. A `missing` entry is never parked (there is no directory to read) and its branch is never deleted, so its commits stay reachable; the result still lists it as `missing`. A short window remains between that second read and `git worktree remove`; `docs/loop.md` states it. The tests use the injected clock of `presenceTiming` and a lock file written by the test, with no sleeps; a hook between the first listing and the removal lets `TestPruneRechecksBeforeRemoval` open a delivery in between. `Prune` never launches an executor or a reviewer.

**Task 9.** A new flag needs three edits in `cmd/batuta/main.go`: the flag definition in `runLoop`, the mutual-exclusion checks beside the ones for `--reconcile`, and the `usage` string. `reconcileField` is the helper that escapes a path for TSV. `--prune` accepts `--workspace` and `--apply` only. `TestLoopPruneUsage` walks the flag set with `flag.FlagSet.VisitAll`, so a flag added later is covered without an edit to the test.
