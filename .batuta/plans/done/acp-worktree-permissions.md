# Plan — ACP worktree permissions: free inside the worktree, contained outside
<!-- inputs: profile.md@sha256:e18a00765937 routing.md@sha256:1615c7990def -->

**Goal:** Let ACP executors work freely inside their worktree and stay contained outside it. An adapter may name the session mode the factory selects (`acp_mode`) and a JSON object sent as `session/new` `_meta` (`acp_session_meta`); the stock factory replaces its deny-all permission policy with a worktree policy that allows a request only when every location it names resolves inside the execution's cwd. The docs state the new permission model. Qualification records for the codex and claude bridges come in a later plan, after the conductor re-runs the real lifecycle probes on this code.

## Decisions and context

Go standard library only, conventional commits. Nothing here changes routing, gates or outcomes, and no qualification record changes: codex-acp and claude-agent-acp stay unqualified until the conductor re-runs the lifecycle probes on this code and a later plan records them.

Evidence for every choice is in `.batuta/acp-probes/qualify-2026-09-23/README.md`. With the stock deny-all policy, codex-acp 1.13.1 in its default mode `agent` never asks the client and wrote and deleted outside the workspace; in mode `read-only` it edits and runs shell inside the workspace without asking and asks for anything outside. claude-agent-acp 0.81.1 in mode `default` asks before every edit and command; with mode `acceptEdits`, `_meta.claudeCode.options.sandbox = {"enabled": true, "autoAllowBashIfSandboxed": true}` and a policy allowing only in-workspace edit locations, it edits and runs shell inside and cannot write outside. The adapters will declare `acp_mode: read-only` (codex) and `acp_mode: acceptEdits` plus that `acp_session_meta` (claude) in a skills PR after this plan.

**Task 1.** Parse the two fields in `executor/adapter.go` next to `acp_run`/`acp_version`/`acp_model_config`/`acp_effort_config` (~119); `ACPLaunch` lives in `executor/transport.go` (~23). `session/new` params are built in `executor/acp/session.go` (~96); keep `Meta` as `json.RawMessage` and send it only when non-empty. Select the mode like the model (`selectOption` by category `mode`, ~109) and check it in `checkConfiguration` (~215) so the enforcing pass covers drift. Reuse the fakes in `session_test.go` (`configState` builds model and thought_level options; add a mode option in the new tests' states).

**Task 2.** Put the policy in the new file `executor/permission_policy.go` with the signature `func(context.Context, Execution, acp.PermissionRequest) string`. Locations come from `request.ToolCall.Locations[].Path`. Resolve cwd with `filepath.EvalSymlinks`; for each location, clean it, require it absolute, resolve the longest existing prefix with `EvalSymlinks` and rejoin the rest, then require the result equal to cwd or under cwd plus a separator. `execute` requests carry no locations and are rejected; the providers' sandboxes run in-worktree commands without asking. The rejection path in `executor/acp/permission.go` stays terminal and is not touched.

**Task 3.** The paragraph to replace starts "ACP permission requests are structured control messages. The stock factory denies every new permission request" (docs/dispatch.md ~176). Keep the sentences about cancellation acknowledgement and verified shutdown. The existing native test's permission request (`executor/acp_native_test.go` ~114) names no location, so it stays rejected under the new policy.
