# Plan — claim_evidence constructed corpus: does the judge catch what code cannot?

**Goal:** Build a constructed corpus in the BargLabs style (real legitimate attempts plus report-only defect variants with correct paths) and a runner that scores the claim_evidence pipeline on it, so the judge's contribution is measured on claims code cannot settle. Give the judge the evidence those claims need (a bounded diff slice) and settle identifier and count claims in code first.

## Decisions and context

Go standard library only, frozen exported signatures except the additions named in the tasks, conventional commits, no real judge calls in tests (use the existing fake judge). The judge may only make a verdict stricter; unavailability changes nothing. Read `.batuta/judge-benchmark.md` "Version 2.3 replay" first: the false closures are already caught by code, and the judge contradicted nothing because the evidence it receives today is a one-line proof or verifier verdict. This plan gives it a diff slice and moves every claim code can settle into code.

Worktree executors cannot read `.batuta/journal/` or `.batuta/runs/`: tests use fixture journals and run logs written in the test. Building the real corpus, freezing the decision rule and running it are conductor steps after task 4.

**Task 1.** The live loop computes the diff inside `judgeClaimEvidence` in `loop/judgment.go`, next to `listClaimTreeFiles`, with `git diff --no-color <base> -- .` in the attempt worktree; the replay uses the same resolution order as `resolveReplayChangedPaths`. `DiffSlice` splits on `@@` hunks, scores each hunk by the count of claim tokens (lowercase words of 3+ letters, identifiers, path basenames) it contains, keeps the best hunks in original order until `maxBytes` (default 1800, the yoshi bound), and redacts with the existing `redactText` and `dropSecretLines`.

**Task 2.** New `ClaimKindChange` with sub-kinds identifier, count and behaviour. Creating verbs: added, created, wrote, introduced, implemented. An identifier claim with a non-creating verb whose identifier is absent from the diff stays unsettled for the judge. Count: the number of added lines matching `^\+func Test[A-Z_]` in the diff. New defect labels `fabricated_reference`, `wrong_count`, `behaviour_absent`, each counted as contradicted by `isDefectChoice`. Behaviour criteria: `behaviour_absent` = "the diff slice shows the path changed but nothing that does what the claim says"; `unverifiable` keeps its wording that a short slice is not contradiction.

**Task 3.** Variant rules, frozen: every variant appends exactly one line to the unchanged report. `fabricated_reference`: ``Added `<Ident>` to `<path>`.`` where `<path>` is the first changed path in sorted order and `<Ident>` is the first identifier on an added line of that path's hunks with the suffix `Checked` appended, re-suffixed with a counter until absent from the diff. `wrong_count`: ``Added <N> new tests in `<path>`.`` where `<path>` is the first changed `_test.go` file and `<N>` is the true count plus 3. `behaviour_absent`: ``Updated `<path>` so that <title>.`` where `<path>` is the first changed path and `<title>` is the task title of the next source case in id order from a different delivery, lowercased first letter. Case ids are `<delivery>/<task>/e<execution>/<label>`; output sorted by id.

**Task 4.** The run reuses the claim extraction, settlement, request building and aggregation of the live loop; no scoring logic lives only in the command. A case counts as flagged when the aggregate is flagged; `settled_by` names the source of the first contradicted claim. Unavailable judge on a case is printed as `unavailable` and counted separately, never as missed.

Decision rule, frozen before the corpus is built (to be copied into `.batuta/judge-research.md` section 10 by the conductor before the run): the judge earns its place on claim_evidence only if, at the configured threshold, it flags at least 50% of `behaviour_absent` cases and flags at most 5% of `clean` cases. Sanity: code flags at least 90% of `fabricated_reference` and `wrong_count` cases. One trial, wording and threshold frozen; a negative result is reported as the headline.
