## Decisions and context

Issues: https://github.com/batuta-ai/core/issues/37, /39, /43, /35, /29, /41. Repository map in `.batuta/profile.md`. Nothing here routes to `self`.

**Sandbox note for executors.** The codex sandbox cannot write Go's default build cache nor the user cache dir. Run tests as `GOCACHE=/private/tmp/batuta-followups-go-cache HOME=/private/tmp/batuta-followups-home go test ./<pkg> -run <Test>` (same variables for `go test ./...` and `go build`). `create preflight scratch failed` or `operation not permitted` on the cache is the sandbox, never the code, and never a reason to stop. A red test you just wrote is the expected first step of test-first work, not a failed command under stop condition 2. `git commit` may be refused inside the sandbox (index.lock): leave the changes in the tree.

**Fixtures (tasks 1, 2).** Every helper that runs `git init` in a test sets, right after it: `user.name t`, `user.email t@example.com`, `commit.gpgsign false`, `gc.auto 0`, `gc.autoDetach false`, `maintenance.auto false`. Where product code creates the repository itself (`repository.Bootstrap`) the test cannot configure it first: that test alone isolates itself with `t.Setenv("GIT_CONFIG_GLOBAL", <path of an empty file in t.TempDir()>)` and drops `t.Parallel()` (Setenv and Parallel are incompatible). The fixture clock in `loop/loop_test.go` (`Now: func() time.Time { clock = clock.Add(time.Second); return clock }`, around line 197) is read and written from parallel attempt goroutines: guard it with a `sync.Mutex` inside the closure. Do not touch production code for either task.

**doctor (task 3).** `inspectGit` in `cmd/batuta/main.go` (line ~325) runs `git status --porcelain`; today `clean` is "no entries". Classify entries with `worktree.IsManaged(path)` (path is the entry from column 3 on, renames split on ` -> `): all managed → state `managed`; none → `clean`; otherwise `dirty`. `doctorReport` gains `GitState string \`json:"git_state,omitempty"\`` with those three values; `GitClean` stays and is true only for `clean`. `printDoctor` prints `clean tree`, `managed state only (WORK.md, .batuta/) — fine for /batuta, commit before batuta loop`, or `dirty tree — commit or stash before delegating`. Same predicate the loop's preflight uses (`loop/runner.go` ~line 412, `worktree.IsManaged`), so the two never disagree.

**Gate subcommands (tasks 4–8).** `cmd/batuta/gate.go` already holds `runGate` and `runGateTree`; add one `runGate<Name>` per gate and dispatch on the name. Shared rules: `--dir <d>` defaults to the current directory and goes through `workspaceRoot`; every subcommand prints one compact JSON object (or array for `proofs`) followed by a newline and nothing else on stdout; exit 0 when the verdict passes, 2 when it fails (`return &ExitError{Code: 2, State: "<gate> failed"}`, which `main` turns into a silent exit 2), 1 on a usage or runtime error with `batuta: <reason>` on stderr; `flags.SetOutput(io.Discard)` like `tree`. The JSON is the `gates.Verdict` (`name`, `pass`, `signal`, `detail`) unless stated otherwise.
- `gate tests --command "<cmd>" [--dir <d>] [--timeout <duration>]`: `gates.NewShellRunner(timeout)` (default 15m) then `gates.Tests(ctx, shell, dir, command)`; prints the Verdict. Missing or empty `--command` → exit 1.
- `gate scope --base <sha-or-ref> --scope <a,b,c> [--dir <d>]`: resolve the base with `git rev-parse --verify <base>^{commit}` (an unknown ref → exit 1); `worktree.New(ctx, root)` then `ChangedPaths(ctx, dir, sha)`; `gates.Scope(changed, scope)` for the verdict; also compute `outside` (changed paths not managed and not `gates.InScope`) and `managed` (`worktree.IsManaged`) and print `{"name":"scope","pass":…,"signal":…,"outside":[…],"managed":[…]}` with empty arrays, never null. `--scope` splits on commas, entries trimmed; an empty list means no Scope declared and passes, as `gates.Scope` does.
- `gate proofs --accept "<criterion → proof>;<criterion → proof>" [--dir <d>] [--timeout <duration>]`: split `--accept` on `;`, `gates.ParseCriteria`, `gates.Proofs(ctx, shell, dir, criteria)`; print the `[]Verdict` as a JSON array; exit 0 when every verdict passes. A criterion without an arrow gets the "left to the verifier" verdict `Proofs` already produces.
- `gate verifier --criteria <n> [--proofs '<json array of gates.Verdict>'] < output`: read stdin to EOF, `gates.Verifier(output, n, proofs)` (nil proofs when the flag is absent; malformed JSON → exit 1); print the Verdict.
- Task 8 adds `"gate"` to `var commands` in `main.go` (alphabetical), lists the five forms in `usage`, rewrites the package doc comment, flips `TestGateIsNotAdvertisedByCapabilities` into a test that expects `gate`, and in `docs/loop.md` documents the five subcommands with their flags and exit codes and removes the `batuta gate` bullet from "Not in this release" (drop the whole section when it becomes empty). The skills' `verification.md` is updated by the conductor in the same release window; not part of this plan.
- Test fixtures for the gates: reuse `committedGitRepository` in `cmd/batuta/gate_test.go`; drive `run(args, &stdout, &stderr)` directly; for stdin-reading commands expose the reader through a package-level `var stdin io.Reader = os.Stdin` that tests replace, or pass it through `run`'s signature only if every caller stays unchanged.

**Plan directories (task 9).** New layout: active plans at `.batuta/plans/<slug>.md`, finished plans at `.batuta/plans/done/<slug>.md`; the legacy `.batuta/plan-<slug>.md` keeps loading for one release. `routing`: `PlanPath(slug)` returns the new active path; new `PlanLocations(slug) []string` returns the active path then the legacy one; `LoadPlan` tries them in order and `Plan` gains `Path string` (workspace-relative, the location that was read); `ListPlans` reads `.batuta/plans/*.md` and the legacy `.batuta/plan-*.md`, never `done/`; the slug regex and the 4 KiB / entry-count limits stay. `loop`: `r.planPath` comes from `Plan.Path`; the `delivery_opened` detail's `PlanPath` carries it; when `tickPlan` writes `**Status:** done` it moves the file to `.batuta/plans/done/<slug>.md` (`os.MkdirAll` + `os.Rename`) and the bookkeeping commit stages both the removal and the new file (`git add -A -- <old path> .batuta/plans`); a plan that is not done stays where it is. `docs/loop.md` "Files the loop writes" names the new paths. Tests: `routing/plan_test.go` gains `TestPlanLoaderReadsBothLocations`; `loop/loop_test.go` moves the fixture plan to `.batuta/plans/greetings.md` and adds `TestLoopMovesAFinishedPlanIntoDone` (delivery done → file under `done/`, old path gone, commit contains both). The plan this delivery runs from sits at the legacy path and is read by an older binary; nothing in this task may break loading it.

**Conventions that matter here.** Standard library only. Tests table-driven, `t.Parallel()` where the test allows; temp dirs through `filepath.EvalSymlinks`. `cmd/batuta` must build with `GOOS=windows` (no bare `syscall`, no `/bin/sh` assumptions outside `gates.NewShellRunner`). Do not touch `CHANGELOG.md`, release-please files, `.goreleaser.yaml`, `.github/`. Frozen signatures: `NewArtifactLoader`, `BuildCandidateBindings`, `Selector.Select`, `RecordFailure`, `SettleWave`.
