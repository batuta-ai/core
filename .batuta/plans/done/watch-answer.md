## Decisions and context

Dependencies for this plan: `charm.land/bubbles/v2` v2.2.1 (its dependency `charm.land/lipgloss/v2` comes along; use lipgloss only through the components, never in the frame) joins `charm.land/bubbletea/v2` v2.0.9 and `github.com/charmbracelet/x/exp/teatest/v2`. The conductor already ran `go get` and committed `go.mod`/`go.sum`; the module cache holds everything. Do not edit `go.mod` or `go.sum`, do not run `go mod tidy`. Every Go command in the sandbox is prefixed with `HOME=/private/tmp/batuta-home GOCACHE=/private/tmp/batuta-gocache GOPATH=/Volumes/Home/francisross/go GOMODCACHE=/Volumes/Home/francisross/go/pkg/mod GOFLAGS=-mod=mod GOPROXY=off` (`GOTOOLCHAIN` stays `auto`). Environment setup is never a question: apply the recipe and continue. Read APIs from the cache: `go doc charm.land/bubbles/v2/textarea`, `go doc charm.land/bubbles/v2/list`, `go doc charm.land/bubbletea/v2 KeyboardEnhancements`, `go doc charm.land/bubbletea/v2 Key`. The executors' sandbox has no terminal: tests build strings and send messages through teatest or direct `Update` calls; never open a pty, never enter raw mode.

Architecture, unchanged: `PanelModel` (journal → view), `Render` (view → frame, paint layer inside), `watchModel` in `loop/watch_tui.go` (Bubble Tea program: navigation, focus, animation, poller in `loop/watch_poll.go`). Overlays are rendered by the watch model below the frame (the frame is cut to leave room, as the legend does today) and never enter `Render`, so every golden stays byte-identical; they are gated off in `Snapshot` and the no-TTY path. The lock file lives next to the journal (`.batuta/journal/<delivery>.lock`, already excluded from git by the `.batuta/journal/` line in `.git/info/exclude`); it is the only new artefact. No process listing (`ps`, `/proc`, `tasklist`): presence comes from the lock's freshness only, the same on linux, darwin and windows.

**Task 1.** The quit rule today is `loop/watch_tui.go` lines 88 and 156 (`state != "" && state != StateBlocked` → `tea.Quit`): delete both; the terminal state only feeds the attention banner (states and texts through `loop/panel_labels.go`, existing paint kinds). The lock is written by the `Runner` (`loop/runner.go`: `Run` at line 690 opens or resumes the delivery; the terminal paths write `KindTerminal`), refreshed by a goroutine with a ticker stopped through the run's context, and removed in a deferred call at the end of `Run` so every exit path, including the question exit and a recovered panic, clears it; the lock's pid is `os.Getpid()`, the host `os.Hostname()`. `Presence` is a pure function over the directory listing plus `now`; the poller in `loop/watch_poll.go` calls it on every tick and puts the result in the `journalMsg` (a lock change alone must trigger a redraw, so the poller also compares the lock mtimes). `PanelHeader` gains `Presence string` (`running`, `stale`, `none`) and `Loops int`; the header paints them; goldens carry the empty presence and `Loops` zero, which render nothing, so nothing changes.

**Task 2.** `loop.Answer(workspace, taskRef, text)` in `loop/report.go` line 444 records the answer and returns the delivery id: the overlay calls it and nothing else in this task (task 3 adds the resume). The overlay state (`answering bool`, `textarea.Model`, the question text) lives in `watchModel`; when `answering` is true every key goes to the textarea except the submit keys, esc, and ctrl+c. Submit keys as `tea.KeyPressMsg` strings: `ctrl+enter`, `alt+enter`, `ctrl+s`; enable `KeyboardEnhancements{ReportAllKeysAsEscapeCodes: false, ReportAlternateKeys: false, ReportEventTypes: false}` is not enough for ctrl+enter — check `go doc charm.land/bubbletea/v2 KeyboardEnhancements` and set what the doc says disambiguates modifiers (the Kitty "disambiguate escape codes" flag; in v2 requesting any enhancement enables disambiguation), and keep alt+enter and ctrl+s as the fallbacks that every terminal reports. The question text comes from the model's `Detail.Question`; the textarea width is the frame width minus 4, height min(8, lines available), `Placeholder` in the current language.

**Task 3.** The watch's own executable is `os.Executable()`; argv `[exe, "loop", "--resume", delivery]`, `Dir` the workspace root returned by `openStore`, stdin `os.DevNull`, stdout and stderr the same `*os.File` opened with `O_APPEND|O_CREATE|O_WRONLY` on `.batuta/runs/loop-<delivery>.log`, then `cmd.Start()` and `cmd.Process.Release()`; `SysProcAttr` in `loop/detach_unix.go` (`Setsid: true`) and `loop/detach_windows.go` (`CreationFlags: syscall.CREATE_NEW_PROCESS_GROUP | 0x00000008`) behind build tags. The spawn is a function field on the model (`spawn func(argv []string, dir, logPath string) error`) replaced in tests. The resumed loop inherits the watch's environment; the sandbox recipe reaches executors through their briefs, so nothing else is needed, but the docs (task 5) say it.

**Task 4.** The list items come from the journal store (`store.List()` and the first and last records of each journal: slug, state through `terminalState`, opened time, last record time) plus `Presence`; keep the read cheap (first line and last line of each file, no full parse). `list.New(items, list.NewDefaultDelegate(), width, height)`, `SetShowTitle(false)`, filtering on by default, `SelectedItem()` on enter. Switching delivery resets navigation and the poller's baseline. `Watch` today prints `no open deliveries` and returns when nothing is open (see `panelDelivery` in `loop/panel.go`): with a TTY it now starts the program with the picker open; `Snapshot` keeps the message.
