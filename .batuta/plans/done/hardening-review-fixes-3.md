**Task 1.** Findings to close, verbatim from the review:
- [1] blocker · loop/attempt.go:188 · premise: Adapter.Outcome parses reset information from the last 20 lines of each stream. This assignment replaces that result using the entire output, and ResetTime selects the first matching epoch. · path: An executor prints an earlier test/example containing reset_at=4102444800, followed by more than 20 ordinary lines, then an actual rate-limit message naming a reset 30 minutes away. Outcome selects the actual reset; this assignment selects the earlier example instead, triggering fallback beyond the default two-hour horizon. · verdict: A reset within the horizon incorrectly switches runtimes; without a fallback, the loop instead waits until the unrelated example timestamp. · fix: Recompute ResetTime with r.now() using the same bounded output tails as Adapter.Outcome. Add a deterministic regression covering an earlier misleading reset timestamp.
- [2] blocker · loop/presence.go:258 · premise: journal.Store.Read returns an empty slice without error for an empty journal. Store.Append creates the journal before writing its first record, so a crash between those operations can leave an empty journal and a presence lock. · path: After the lock becomes stale, Resume calls acquireDeliveryOwnership, which replaces the lock and calls journalPresenceTakeover. This indexes records[len(records)-1] without checking its length. · verdict: Recovery panics with an index-out-of-range error instead of returning a controlled error, leaving the newly acquired lock behind. · fix: Handle zero records before indexing, returning an error so acquireDeliveryOwnership stops and releases the replacement owner. Add a regression test for takeover with a stale lock and an empty journal.
- [5] blocker · worktree/git.go:225 · premise: Park initializes its temporary index from HEAD and then replaces entries with working-directory contents; it never captures the real index's staged contents. · path: Stage a new file, then remove its working-directory copy before an executor failure. Park builds the HEAD tree and can return success without a recovery ref. Subsequent forced worktree removal deletes the real index containing the only reference to the staged blob. · verdict: Staged executor work is absent from recovery snapshots and can be permanently lost after garbage collection. · fix: Preserve the real index tree in an additional protected snapshot before cleanup, alongside the working-directory snapshot. Add a regression covering a staged new file removed from the working directory.
- [7] major · loop/report.go:41 · premise: The terminal record serializes summary.Parked before CleanParked removes integrated snapshots at line 56. · path: When integrated parked refs exist, finish journals those refs, deletes them, and updates only the local summary used for printed output. TestLoopDeletesIntegratedParkedRefs already supplies this execution path. · verdict: The persisted terminal summary lists recovery refs that no longer exist and disagrees with the printed terminal summary. · fix: Persist the terminal summary with the retained ref list after successful cleanup, using a recoverable finalization sequence if terminal recording must precede deletion.
- [8] major · loop/report.go:51 · premise: finish records a final KindTerminal before attempting worktree removal. GitProvider.Remove can fail, for example when a worktree is locked. · path: A removal failure returns here before bookkeeping and printSummary. Resume and Abandon subsequently reject the delivery because its journal already contains a final terminal state. · verdict: Cleanup failure leaves plan ticks and WORK.md unfinished, suppresses the recovery summary, and prevents retrying finalization through the supported commands. · fix: Make finalization recoverable, or record retained-worktree cleanup failures and continue bookkeeping and summary output before returning the cleanup error.

The flaky test: `TestLoopResumesAfterAStopBetweenWaves` (`loop/loop_test.go` ~line 660) failed once under `go test -race ./...` with `progress before resume = 8, want 4`: the stop raced the admission of the next wave, which ran and emitted its progress. Stop the run at a deterministic point (the fixture's scripted executor can block the second wave's attempt on a channel the test closes only after asserting, or the fixture clock can drive the stop) so exactly one wave runs before the stop. `Adapter.Outcome` and its bounded tails are in `executor/adapter.go`; `journalPresenceTakeover` in `loop/presence.go` ~line 258; `finish` in `loop/report.go` ~lines 41–56; `Park` in `worktree/git.go` ~line 225.

**Task 2.** Findings to close, verbatim from the review:
- [3] blocker · review/manifest.go:182 · premise: A Git pathspec also matches descendants. When tracked file `pkg` is deleted and replaced by tracked `pkg/a.go`, diffing `-- pkg` returns both files' patches. · path: inspectFile passes that combined diff to parseDiff, which assigns every hunk and line count to the deleted `pkg` entry. cohortDiff repeats the same selection, so prompt validation accepts the contaminated ranges. · verdict: The manifest double-counts the child's changes and gives a deleted file reportable new-side lines belonging to another file. · fix: Parse patches by file identity and retain only the intended entry, using the same filtering for manifest accounting and cohort prompts. Add a file-to-directory replacement regression test.
- [4] blocker · review/report.go:257 · premise: The tracked-path guard treats every filesystem directory as a safe parent, including tracked gitlinks for initialized submodules. · path: With --out submodule/reports, the superproject's ls-files does not list submodule/reports/review.md, even when tracked inside the submodule. Checking the submodule parent succeeds, but os.Stat reports a directory, so the guard permits publication. WriteArtifacts then replaces the tracked review.md using os.Rename. · verdict: Review can overwrite tracked submodule content, including local edits. The subsequent tree check occurs after replacement and cannot prevent that data loss. · fix: Inspect exact index entries and reject destinations beneath gitlinks before publication, or validate destinations against the owning submodule's index. Add a regression case proving tracked submodule artifacts remain untouched.
- [6] major · cmd/batuta/main.go:782 · premise: reviewSessionError treats every WorktreeState error as evidence of a source-tree mutation and discards both stateErr and sessionErr. · path: Interrupting an active review cancels ctx. The subsequent WorktreeState call uses that canceled context, so its Git subprocess fails even when no files changed. Execution then returns the unconditional source-tree-changed error. · verdict: An interrupted review falsely reports a source mutation and hides the cancellation or underlying Git failure. · fix: Handle stateErr separately and preserve its cause alongside sessionErr. Report a source mutation only when a successful snapshot comparison proves one; use a fresh bounded context if verification must continue after cancellation.
- [9] major · review/prompt.go:53 · premise: BuildSpecPrompt filters the manifest to selected, nonignored files, although the spec sweep explicitly requests the complete diff summary. · path: A changed generated file or go.sum remains in manifest.Files but is omitted from the dedicated spec verifier's summary, including when acceptance criteria concern that file. · verdict: The spec verifier receives an incomplete delivery inventory for judging all criteria. · fix: Include every manifest file in the spec summary, annotating ignored and selection status instead of excluding entries; test a criterion involving an ignored changed file.
- [10] major · review/state.go:137 · premise: Covered cohorts are omitted from pending state even when the spec sweep is uncovered; state_test.go explicitly expects no pending files for this case. · path: Run with --worktree and --spec while a new file is untracked. On the next incremental run without --worktree, BuildIncrementalManifest cannot restore it, so BuildSpecPrompt omits it from the diff summary. · verdict: The retry loses part of the diff whose spec conformance remains unverified, allowing the sweep to assess an incomplete change set. · fix: Preserve selected untracked files while spec coverage is incomplete, and add a regression covering a failed spec sweep followed by an incremental retry without --worktree.
- [11] minor · docs/review.md:94 · premise: The documentation says overlapping ranges suffice for suppression, but review/findings.go Merge also requires matching, nonempty normalized Rule values; suppressLintOverlaps delegates to Merge. · path: A reviewer finding overlaps a lint diagnostic but has an empty or different rule.
