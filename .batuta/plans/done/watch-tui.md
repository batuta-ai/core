## Decisions and context

Dependency policy for this plan, revoking the "standard library only" line of plan `dashboard`: the module gains `charm.land/bubbletea/v2` v2.0.9 (framework) and `github.com/charmbracelet/x/exp/teatest/v2` (tests only). Nothing else from Charm: no `bubbles`, no `lipgloss`; layout, glyphs, ANSI 16 colours and the goldens stay in `loop/panel_render.go`. No cgo. `cmd/batuta` keeps building on linux, darwin and windows (Bubble Tea v2 drives the Windows console itself). The conductor ran `go get` for both modules and committed `go.mod`/`go.sum` before the loop started, and the module cache under `GOMODCACHE` already holds them: executors never download. Every Go command in the sandbox is prefixed with `HOME=/private/tmp/batuta-home GOCACHE=/private/tmp/batuta-gocache GOPATH=/Volumes/Home/francisross/go GOMODCACHE=/Volumes/Home/francisross/go/pkg/mod GOFLAGS=-mod=mod GOPROXY=off` (`GOTOOLCHAIN` stays `auto`; go1.26.4 is in that cache). Environment setup is never a question: apply the recipe and continue. Read the framework's API from the cache, not from memory: `go doc charm.land/bubbletea/v2 Model`, `go doc charm.land/bubbletea/v2 View`, `go doc charm.land/bubbletea/v2 KeyPressMsg`, `go doc github.com/charmbracelet/x/exp/teatest/v2`. In v2 `View()` returns `tea.View` (fields `Content`, `AltScreen`, `MouseMode`, `WindowTitle`), `Update` returns `(tea.Model, tea.Cmd)`, key presses arrive as `tea.KeyPressMsg` whose `String()` gives `"q"`, `"ctrl+c"`, `"up"`, `"pgdown"`, and the window size as `tea.WindowSizeMsg{Width, Height}`.

Layer contract, unchanged from plan `dashboard`: `PanelModel(records, now, selected) PanelView` is the only reader of the journal; `Render(model PanelView, style Style) string` is the only producer of a frame; `docs/dashboard-mock/*.txt` and `loop/testdata/*.txt` are the goldens and never change in this plan (the proof `git diff --quiet -- docs/dashboard-mock loop/testdata` guards every task that touches the renderer). The Bubble Tea model owns navigation, focus, animation state and the terminal size, and calls those two functions. `Snapshot` (`--once`) and the no-TTY path call `Render` directly and never start a program.

Testing doctrine: `teatest.NewTestModel(t, model, teatest.WithInitialTermSize(120, 40))`, `tm.Send(msg)`, `teatest.WaitFor(t, tm.Output(), func(b []byte) bool)`, `tm.WaitFinished(t, teatest.WithFinalTimeout(time.Second))`, `tm.FinalModel(t)`; time comes from injected functions (`now func() time.Time`, poll and clock commands built by the model from an injectable `ticker func(d time.Duration, fn func(time.Time) tea.Msg) tea.Cmd`) so no test sleeps for real. Journals for tests come from the fixtures already used by `panel_model_test.go` (five states). The loop test fixture (`loop/loop_test.go`) is not touched by this plan.

**Task 1.** Start from `loop/panel_keys.go`: keep `panelNavigation`, `move`, `viewport`, `panelWindow`, `panelLegend`, `panelAnswerCommand`, `panelLogPath`, `loadPanelLog`, `panelKeyAction`; the new model wraps them. Do not delete `startPanelKeys`, `decodePanelKey`, `panelTerminal` or `watchWithTerminal` yet: task 3 removes them once `Watch` runs the program; until then both paths coexist and `go test ./...` stays green. The `o` key without `$PAGER` only sets the notice to the path. `tea.ExecProcess` takes an `*exec.Cmd` built from `$PAGER` split on spaces plus the log path, with stdin, stdout and stderr left to the framework; its callback returns a `pagerDoneMsg{err}` that becomes the notice on error.

**Task 2.** The poller is a `tea.Cmd` returned after every `journalMsg` (self-rescheduling with `tea.Tick(interval, …)`); it compares `os.Stat` size and mtime of `.batuta/journal/<delivery>.jsonl` and the size of the active run log (from the model's `Detail.LogPath`) to what it saw last, and only then calls `store.Read` and `loadPanelLog`. `interval` is the `--interval` flag (default 500 ms; the CLI default changes in task 3). The clock is a second `tea.Tick(time.Second, …)` chain that only updates `now`. Terminal states are the same as `terminalState(records)` in `loop/panel.go`.

**Task 3.** `Watch` decides TTY-ness with the framework's helper on stdin (whatever `charm.land/bubbletea/v2` exposes; if it exposes none, `os.Stdin.Stat()` mode `ModeCharDevice`), and the colour decision in `StyleForWriter` likewise for the output writer, so the four `rawmode_*`/`termsize_*` files and the `syscall` imports disappear from `loop/`. The no-TTY fallback keeps the old contract of `TestWatchWithoutATTYAutoFollows`: frames separated by a blank line, no escape sequences, exit on terminal state. `--interval` default becomes 500 ms in `cmd/batuta/main.go` and its help text says "journal poll interval". Windows build is a proof, not a hope: run it. The helper is `IsTerminal(fd uintptr) bool` from `github.com/charmbracelet/x/term` (already required by go.mod as an indirect dependency of Bubble Tea; import it, do not edit `go.mod`/`go.sum`, do not run `go mod tidy`). `Watch` takes the terminal decision through an injectable `isTerminal func(uintptr) bool` (package-level variable or a field of the options) so `TestWatchRunsTheProgram` forces the TTY path and builds the program with `tea.WithInput(strings.NewReader("q"))`, `tea.WithOutput(&buf)` and `tea.WithoutRenderer()`: the test never opens a pseudo-terminal and never enters raw mode, because the sandbox that runs your tests has no terminal and forbids raw mode (`error entering raw mode: operation not permitted` was the failure of the first attempt). The first delivery of this task was lost to a loop defect (core #70): its executor's work was discarded after a question. Deliver it again from scratch.

**Task 4.** Animation must never change a golden: goldens render with `Style.Frame == -1` and integer progress; the eased floats are rounded the same way the integers were (`WavesShown == float64(WavesDone)` at the end of the easing). The spinner tick is a `tea.Tick(80*time.Millisecond, …)` chain started when a running task appears and not rescheduled when none is running. Easing: linear over 12 frames is enough; no bounce.

**Task 5.** Focus is a field of the model (`focusTable`/`focusLog`); the renderer only sees which box is focused and a log scroll offset: `Style.Focus string` (empty in goldens) and `Style.LogOffset int` (zero in goldens, meaning follow the tail) in `loop/panel_render.go`, so `PanelView` needs no new field. `fitPanelHeight` in `loop/panel.go` must stop truncating `LogLines` before the viewport: the model keeps the whole tail read from the file (last 200 lines), and the renderer slices the visible window from `LogOffset` and the box height, so scrolling reaches older lines at any terminal height. The key line below 100 columns lists `l log` too, and the tests cover 120 and 80. Two deliveries of this task were lost to loop defects (core #70, core #71); start from the base, the worktree is empty. Mouse mode goes in the `tea.View` (`MouseMode: tea.MouseModeCellMotion`); the wheel message type is `tea.MouseWheelMsg` with a `Button` of `tea.MouseWheelUp`/`tea.MouseWheelDown` — confirm with `go doc`.

**Task 6.** Task 5 of plan `roadmap` once replaced `docs/loop.md` with a stub; the first criterion counts headings against `HEAD` so that cannot happen again. The dashboard section is the one titled with "dashboard" or "watch" (`grep -n -i 'dashboard\|watch' docs/loop.md`); extend it, do not move it.
