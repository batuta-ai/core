State after `ed62257`. The grant hook is in `runAttempt` (`loop/attempt.go:323-357`). It already replies only while `grantTurns < 3`, skips a question already seen in this execution through `seenQuestions` (exact text, not normalized), and fixes `deadline := r.now().Add(r.opts.TaskTimeout)` at the execution's first dispatch (`attempt.go:309`). Each dispatch gets `deadline.Sub(r.now())`, a turn with no time left falls through to `recordQuestion`, and a usage limit wait adds its delay to the deadline. Task 1 normalizes the repeat check (whitespace collapsed, trimmed), keeps those rules, and adds the tests. Time is read through `r.now`, the clock from `Options.Now` that the test fixture already injects and advances by one second per call (`loop/loop_test.go:369-374`), so tests never sleep. Grant turns never touch `TokenAllowance`. Fake-executor scenarios needed: one alternates two questions, one keeps asking new covered questions. Existing grant scenarios sit near `loop/loop_test.go:158`.

**Task 2.** `recordQuestion` is at `loop/attempt.go:886`. The ask file body is built at `:899-902` and the `question_recorded` detail at `:909`. Pass it the park reason and the uncovered items from the hook. Add the keys `grant_park` (`not_covered`, `malformed_clause`, `turn_cap`, `repeat` or `deadline`) and `beyond_grant` (the uncovered items, only for `not_covered`) only when the standing grant is non-empty. A question without a grant keeps today's detail and ask file byte for byte. Fake-executor scenarios needed: one asks with an uncovered `Beyond grant:` item, one with a malformed clause.

**Task 3.** Replay (`settle.go:280-330`) keys dispatches per task and execution, and the last record wins. CLI attempts keep their retry policy, while ACP intents and submitted results stay parked until reconciliation (`settle.go:385-407`); keep that rule. Build the test journals by hand, without running the runner, with a `grant_replied` fixture from `loop/grant_turn_test.go`. The carrier of a pending reply is a new `Runner.grantReplies map[string]grantReply` in `loop/runner.go`, keyed like the other replay maps (`attemptKey(task, execution)`), and filled by replay in `settle.go` from the last `grant_replied` of an execution. Replay rule for the second window: a dispatch that finished with a question, has a later `grant_replied`, has no `question_recorded` and has no later dispatch of the same execution is an interrupted run, not a parked question. On CLI, both crash windows resume as exactly one interrupted execution, which consumes one execution, as accepted. When `runAttempt` builds the brief of the next execution, it sets `BriefInput.GrantReply` from `grantReplies` of the interrupted execution, so the executor sees the question and the reply. On an ACP dispatch that may have submitted, the outcome is the existing `blocked` with `submission_uncertain`. `SettleWave` and `RecordFailure` keep their signatures.

Test HOME. Executor sandboxes cannot write `~/Library/Caches`, and the integration preflight takes its scratch from `os.UserCacheDir()` (`integration/git.go:724`), so a test that runs the runner end to end fails there with `integration: create preflight scratch failed`. Every new or changed test that calls `New` or `Resume` and then `Run` first sets `HOME`, `XDG_CACHE_HOME` and `LocalAppData` to one `tempDir(t)`, as `TestLoopWorktreesInCacheHome` does (`loop/loop_test.go:450-454`). Put that in one helper in `loop/grant_turn_test.go` and call it from `runGrantedQuestion` and every new end-to-end grant test. Those tests then cannot use `t.Parallel`, because `t.Setenv` forbids it.

Proofs. Every named proof has the form `out=$(go test -run '^Name$' -v ./pkg/) && printf '%s' "$out" | grep -q -- '--- PASS: Name '`. It requires `go test` to exit 0 and the exact test name, followed by a space, to pass. The package gate is `go test -timeout 30m ./loop/`: on 2026-10-25 the suite took 1246s on a loaded machine and timed out twice at 15m with no failing test. Known flakes, where a rerun is the response and never a skip: `TestLoopStopsWorktreeProcesses` (one input/output failure), and under full-suite load `TestNativeTransportFreshOwnedConnection` (`executor`) and `TestProcessManagedGroupShutdown` (`executor/acp`), both with `acp: managed process cleanup unresolved`, outside this Scope.
