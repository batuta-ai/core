**Task 1.** The check is `validateCalibrateRecordFields` with its helpers (`cmd/batuta/judge_classify_calibrate.go` ~170–260). The fields the calibrate code reads from a record, all of which must be validated, are: `task`, `split`, `plan_lane`, `outcome`, `open_marker`, `scope` (`Files`, `Directories`, `TestOnly`, `DocsOnly`), for each question in `benchV3Questions` the packet's `found` and `size`, and the answer's `status`, `choice`, `confidence` and `probabilities`; `code_lane` and `judge_lane` are validated too because the record carries them. The record types are in `cmd/batuta/judge_classify_v3.go` ~15–45. The bench writes `choice` and `probabilities` with `omitempty`, so they are absent, and allowed to be absent, when the status is not_asked or unavailable; `confidence` is always written and is 0 for those two statuses. The options per question are `exported_change`, `internal_only`, `insufficient` for `contract` and `security_behaviour`, `incidental`, `insufficient` for `security`; take them from the keys the `classify` package already exposes when it exposes them, otherwise as literals in the reader. The outcome values are the `benchOutcome*` constants (`cmd/batuta/judge_classify.go` ~194). For the last-but-two criterion, produce the records by running the real bench against the local HTTP test server the existing bench tests use, so the validation is proven against what the bench writes and not against a hand-written fixture. Error messages name the 1-based line and the field.
