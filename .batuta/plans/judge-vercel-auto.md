## Decisions and context

Go standard library only, frozen exported signatures except additions in the `judge` package, conventional commits, tests against `httptest` only, no secrets anywhere. Read `docs/judge.md` and `.batuta/judge-research.md` first; this plan corrects section 2 of the research note.

Verified on 2026-09-20 from Vercel's documentation (`/docs/ai-gateway/modalities/evaluation`, `/docs/ai-gateway/sdks-and-apis/typesafe`): the gateway serves Jev over raw HTTP in two shapes. The TypeSafe-compatible API at base URL `https://ai-gateway.vercel.sh/typesafe` exposes `POST /typesafe/v1/systemone` and `GET /typesafe/v1/models`, takes TypeSafe's exact request body with `"model": "typesafe-ai/jev"`, header `Authorization: Bearer $AI_GATEWAY_API_KEY`, and returns TypeSafe's response shape (`noul`/`choice`/`score`, `usage.input_tokens`) plus a `provider_metadata.gateway` object with `cost` and `generationId`; errors are `{"message": "...", "error_type": "invalid_request"}` and provider errors pass through unchanged. The gateway-native API at `POST https://ai-gateway.vercel.sh/v1/evaluate` uses `boolean` instead of `noul`, `probability` instead of `noul`, camelCase `usage.inputTokens` and `providerMetadata`; the judge does not use it, so the one parser stays.

**Task 1.** In `judge/http.go`, `ProviderVercel` becomes a real provider: default base URL `https://ai-gateway.vercel.sh/typesafe`, path `/v1/systemone`, default model `typesafe-ai/jev`; keep an explicit `BaseURL` override for tests. Ignore `provider_metadata` when decoding (do not fail on unknown top-level fields). Add a Vercel error mapper next to `openRouterErrorReason`: a body with `error_type` yields reason `gateway_<error_type>` for 4xx other than 429 and keeps `rate_limited`/`server_error` for 429/5xx. Remove the `transport_undocumented` reason from the reasons list, the tests, `docs/judge.md` and the research note; rewrite the Vercel row of the providers table in both documents and add the sentence that the judge uses the TypeSafe-compatible route because it needs no second parser. `applyDefaults` already maps `vercel` to `AI_GATEWAY_API_KEY`; keep it.

**Task 2.** New `judge/chain.go`: `Chain{Judges []Named; ...}` where `Named{Provider Provider; Judge Judge}`; `Ask` walks the list in order and returns the first `Response`; an `UnavailableError` whose reason is one of `rate_limited`, `server_error`, `timeout`, `malformed_response`, `key_missing` continues to the next entry, any other error or reason (`state_too_large`, `answer_mismatch`, a non-Unavailable error) returns at once; when the list is exhausted return `UnavailableError{Reason: "all_unavailable"}` wrapping the per-provider reasons in order (exported `ChainError{Attempts []ChainAttempt}` with `Provider` and `Reason` per attempt, reachable through `errors.As`). Config: `provider` gains the value `auto` and an optional `providers` array (`["typesafe","vercel","openrouter"]`, each name once, only these three); `auto` without `providers` means that default order; `model`, `key_env` and `base_url` are rejected together with `auto` (each provider uses its own defaults; per-provider overrides are out of scope). `Config.Judge(getenv)` under `auto` builds the chain from the providers whose key variable is non-empty, in order, and returns `ErrUnavailable` with reason `key_missing` and the three variable names when none is present. `Traced` records gain `provider` on the result (the provider that answered) and `skipped` (list of provider and reason) taken from the chain through a small optional interface the chain implements (for example `LastAttempts() []ChainAttempt`) so `Traced` keeps working with a plain `HTTPJudge`. `batuta judge probe` prints the answering provider in its success line. Document `auto`, the default order (TypeSafe direct first because it is the origin, then Vercel because it keeps TypeSafe's shape, then OpenRouter), the fallback reasons and the exhaustion error in `docs/judge.md`.
