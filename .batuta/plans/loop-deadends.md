## Decisions and context

Invariants of `batuta loop` (docs/loop.md): a new session per attempt; zero questions by default; the four gates decide; a usage limit is a wait, not a failure; one commit per task; no crash may leave a delivery without a terminal record. Every task here serves the last one. The mock engine lives in `loop/loop_test.go` (`fakeExecutor`, `setup`, `fixture.options`, scripted results per execution); the routing graph in `routing/graph.go` (`RecordFailureWithPolicy` around line 750, `RecordQuestion` at line 624, `nextRuntimeForTask`, `MaxTaskExecutions`); the attempt lifecycle in `loop/attempt.go` (`recordFailureWithPolicy` around line 495, `recordQuestion` at line 423, the limit-wait loop around line 175, `blockerSelf` at line 79, the silent-session path around line 240). Blocker codes are the constants at the top of `loop/attempt.go`.

Every Go command in the sandbox is prefixed with `HOME=/private/tmp/batuta-home GOCACHE=/private/tmp/batuta-gocache GOPATH=/Volumes/Home/francisross/go GOMODCACHE=/Volumes/Home/francisross/go/pkg/mod GOFLAGS=-mod=mod GOPROXY=off` (`GOTOOLCHAIN` stays `auto`; go1.26.4 is in that cache). Do not edit `go.mod` or `go.sum`, do not run `go mod tidy`. Environment setup is never a question: apply the recipe and continue. Tests are deterministic: the fixture clock, no sleeps on real time (the limit wait uses `r.sleep`, replaced in the fixture), no network, no pty.

**Task 1.** `tree_changed` today compares a porcelain signature taken at the start of the execution with one taken at the end (`loop/attempt.go` line 214, `before != after`). Replace the baseline with the attempt's `BaseHeadSHA`: changed = `git diff --quiet <base>` fails or untracked files exist (ignore `.batuta/`). The silent-session path (gates 2 and 3 "against the base") must first prove the tree equals the base; when it does not, the tree is a candidate and goes through the normal gate 1–3 route. Journal both signatures so the trail explains the decision.

**Task 2.** The snapshot is the existing `wip(batuta): <slug> candidate` mechanism generalised: same author identity, `commit.gpgsign=false` through `GIT_CONFIG_COUNT`, message `wip(batuta): <slug> <task> e<n> parked`. Snapshot branches are the worktree branches that already exist (`batuta/<slug>/task-<n>-e<m>`); today cleanup deletes them with the worktree — keep the branch, delete only the worktree, and delete branches at the delivery's terminal record when `git merge-base --is-ancestor <tip> <integration branch>` holds; otherwise leave them and list them in the summary as `kept (unmerged work)`. `batuta loop --abandon` follows the same rule.

**Task 3.** The failure policy walks `nextRuntimeForTask`; when the chosen runtime's `Provider == string(ExecutorSelf)`, do not append an attempt: block with `needs_conducting_session` (the constant already exists in `loop/attempt.go` as `blockerSelf`; move the string to a shared place both packages can name, or duplicate the literal with a comment naming the counterpart). The preflight refusal at line 79 stays for tasks routed to `self` from the start.

**Task 4.** `RecordQuestion` today returns `ErrInvalidDeliveryTransition` when the execution has no continuation slot. Turn that case into a blocked task: attempt state blocked, blocker `question_at_ceiling`, `Question` kept. The loop's `recordQuestion` writes the ask file before recording, and prints the blocked line. `loop.Answer` refuses with `task_N is blocked at the execution ceiling; answer the question in a new plan or an interactive cycle`.

**Task 5.** `already_satisfied` is recorded through `recordBlocked` (`FailurePolicy{}`) which marks the task blocked; the settle step then sees a blocked task and ends the delivery. Give the graph a distinct terminal task state for it (satisfied, counted with integrated for dependencies and for the done condition) or record it as integrated with the base sha as `IntegratedCommitSHA` and a flag; either way the wave settles, dependents are admitted and the summary shows `✅ … already satisfied on the base`.

**Task 6.** The fallback runtime is `nextRuntimeForTask(generation, task, runtime)` (routing) — the same cell walk the escalation uses, so no new column in `.batuta/routing.md` for now (#54's `Limit fallback` column is deferred; say so in docs). The switch keeps `execution` and `runID`, records `limit_fallback` `{execution, from, to, reset_at, waits}`, and runs the brief again in the same worktree. `--limit-horizon` is a `time.Duration` flag on `batuta loop` stored in `Options.LimitHorizon` (default 2h); `executor.ResetTime` already parses the reset time when the message names one.

**Task 7.** Probes are the maps at the top of each adapter (`inventory/adapters/cursor.go` lines 10–12: `ids`, `args`, `order`; the `expand` step builds `mcp list-tools` probes at line 36). Drop `mcp` from the three adapters and the expansion from cursor; delete the fixtures that only served them. The slow-probe note comes from the probe durations the inventory already measures (or add a duration per probe result); doctor prints `note: <executor> <probe> took 7.2s (budget 5s)`.

**Task 8.** Task 5 of plan `roadmap` once replaced `docs/loop.md` with a stub; the first criterion counts headings against `HEAD` so that cannot happen again. Extend the existing failure section; do not move it.
