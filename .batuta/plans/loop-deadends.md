## Decisions and context

Invariants of `batuta loop` (docs/loop.md): a new session per attempt; zero questions by default; the four gates decide; a usage limit is a wait, not a failure; one commit per task; no crash may leave a delivery without a terminal record. Every task here serves the last one. The mock engine lives in `loop/loop_test.go` (`fakeExecutor`, `setup`, `fixture.options`, scripted results per execution); the routing graph in `routing/graph.go` (`RecordFailureWithPolicy` around line 750, `RecordQuestion` at line 624, `nextRuntimeForTask`, `MaxTaskExecutions`); the attempt lifecycle in `loop/attempt.go` (`recordFailureWithPolicy` around line 495, `recordQuestion` at line 423, the limit-wait loop around line 175, `blockerSelf` at line 79, the silent-session path around line 240). Blocker codes are the constants at the top of `loop/attempt.go`.

Every Go command in the sandbox is prefixed with `HOME=/private/tmp/batuta-home GOCACHE=/private/tmp/batuta-gocache GOPATH=/Volumes/Home/francisross/go GOMODCACHE=/Volumes/Home/francisross/go/pkg/mod GOFLAGS=-mod=mod GOPROXY=off` (`GOTOOLCHAIN` stays `auto`; go1.26.4 is in that cache). Do not edit `go.mod` or `go.sum`, do not run `go mod tidy`. Environment setup is never a question: apply the recipe and continue. Tests are deterministic: the fixture clock, no sleeps on real time (the limit wait uses `r.sleep`, replaced in the fixture), no network, no pty.

**Task 1.** `tree_changed` today compares a porcelain signature taken at the start of the execution with one taken at the end (`loop/attempt.go` line 214, `before != after`). Replace the baseline with the attempt's `BaseHeadSHA`: changed = `git diff --quiet <base>` fails or untracked files exist (ignore `.batuta/`). The silent-session path (gates 2 and 3 "against the base") must first prove the tree equals the base; when it does not, the tree is a candidate and goes through the normal gate 1–3 route. Journal both signatures so the trail explains the decision.

**Task 2.** Two deliveries of this task failed on the same contradiction: `integration/git.go:77` requires a candidate to be exactly one commit whose parent is the base, so parked snapshots must never sit on the worktree branch. Snapshot = a commit object made from the working tree without moving anything: `GIT_INDEX_FILE=<tmp> git add -A` (untracked included, `.batuta/` excluded), `git write-tree`, `git commit-tree <tree> -p HEAD -m 'wip(batuta): <slug> <task> e<n> parked'`, then `git update-ref refs/batuta/parked/<slug>/task-<n>-e<m> <sha>`; author identity from the configured git user and `commit.gpgsign=false` through `GIT_CONFIG_COUNT` as the integration commit does. Put the helper in `worktree/git.go` (`Park(root, ref, message) (sha, error)`) and call it from `loop/attempt.go` at the three moments; the candidate flow (`Squash`, the one-commit rule) stays exactly as it is, and the two loop tests named in the third criterion are the guard. Refs live in the main repository, so they survive `git worktree remove`; the terminal cleanup walks `refs/batuta/parked/<slug>/*` and deletes a ref only when `git cat-file -p <sha>` tree equals the tree of a commit reachable from the integration branch (compare tree ids), else keeps it and prints it. A previous attempt's partial work is in `.batuta/runs/2026-09-08-loop-deadends-task-2-e3.backup.patch` only if that file exists; do not depend on it.

**Task 3.** The failure policy walks `nextRuntimeForTask`; when the chosen runtime's `Provider == string(ExecutorSelf)`, do not append an attempt: block with `needs_conducting_session` (the constant already exists in `loop/attempt.go` as `blockerSelf`; move the string to a shared place both packages can name, or duplicate the literal with a comment naming the counterpart). The preflight refusal at line 79 stays for tasks routed to `self` from the start.
