# Plan — claim_evidence v2: atomic claims, code first, one choice per claim
<!-- inputs: profile.md@sha256:e18a00765937 routing.md@sha256:1615c7990def -->

**Goal:** Rebuild the `claim_evidence` decision the way TypeSafe documents System One use (`.batuta/judge-research.md` section 7): code extracts the executor's atomic claims and their evidence, settles what it can settle exactly, and asks the judge one `choice` per remaining claim in a single request; code aggregates with confidence gating and an explicit uncertain bucket. Same journal records, same replay command, so the baseline in `.batuta/judge-benchmark.md` is directly comparable.

## Decisions and context

Go standard library only, frozen exported signatures except additions in `loop` and `cmd/batuta`, conventional commits, tests against httptest and fake judges only, no secrets. Read `.batuta/judge-research.md` section 7 and `.batuta/judge-benchmark.md` first: they explain why v1 is being replaced and what the replay must be able to compare. Keep `ClaimEvidenceQuestions` and the v1 state builder exported but unused by the loop, so the baseline can still be replayed with a `--v1` flag if someone asks; do not spend more than that on v1.

**Task 1.** `loop/claims.go`: `type Claim struct { Kind ClaimKind; Text string; Line string; Path string; Criterion int; Status ClaimStatus; Source ClaimSource; Evidence string }` with kinds `path`, `criterion`, `tests`, `commit`, statuses `unsettled`, `supported`, `contradicted`, sources `code`, `judge`. `ExtractClaims(report string, criteria []gates.Criterion) []Claim` works line by line over the bounded report; a path claim needs a repository-relative path token (contains `/` or a known extension, no scheme, no absolute prefix) and dedupes by path. `SettleClaims(claims []Claim, ev ClaimEvidence) []Claim` where `ClaimEvidence{ChangedPaths []string; TreeChanged bool; Proofs []gates.Verdict; VerifierLines map[int]string; TestsPass bool}`; the verifier lines come from parsing the verifier detail with the same `TASK n:` regex `gates` uses. Never call the judge from this file.

**Task 2.** Replace the body of the judgment path in `loop/judgment.go`: build claims, settle, and if any claim is unsettled build one `judge.Request` with `State = {task_id, title, scope, outcome_gates}` and `Questions[claim_<i>] = judge.Question{Type: choice, Instructions: {"question": "How does the evidence relate to the claim?", "claim": ..., "evidence": ...}, Criteria: {"supported": "the evidence states or directly implies the claim", "contradicted": "the evidence shows the claim is false", "unverifiable": "the evidence says nothing about the claim"}}`. Aggregate in code: `flagged = any(code contradicted) || any(judge contradicted && confidence >= threshold)`; `uncertain` collects judge answers with confidence below threshold or whose contradicted probability lies in 0.30–0.70. The `judge_result` detail gains `claims` (the settled list with source, choice, confidence) and `uncertain`; keep the existing fields. `enforce` behavior and the `claim_unsupported` blocker stay; the feedback names the contradicted claim and its report line. Update `docs/judge.md`.

**Task 3.** Replay uses the same builder; the totals line gains `flagged=<n>`; `--json` carries `claims`. Keep the earlier fields and their order so the benchmark file's v1 lines and the v2 lines can sit side by side.
