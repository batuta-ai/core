## Decisions and context

Where this plan and section 14 differ, section 14 wins and the difference is a question for the conductor. v3 goes in new files so v1, v2 and their tests stay untouched. Nothing in `routing/`, `loop/` or `judge/` changes.

Environment setup is never a question. For Go inside a sandbox on this machine: `HOME=/private/tmp/batuta-home GOCACHE=/private/tmp/batuta-gocache GOPATH=/Volumes/Home/francisross/go GOMODCACHE=/Volumes/Home/francisross/go/pkg/mod`, `GOTOOLCHAIN` stays `auto`. Run the tests named in your task's Accept lines. If the sandbox blocks a loopback listener or the Go build cache, write the tests and say so in the report: the conductor's gate runs the whole suite.

**Task 1.** `classify.Features` and `ScopeFeatures` already exist in `classify/v2.go` and are reused as they are. The task's own context paragraph is what `routing.Plan.ContextFor(task.Number)` returns, bounded the way v1 does it (`boundContext`, `classify/classify.go` ~152–190). Lanes are `routing.Complexity` values. The seven markers are: `TBD`, `to be decided`, `to be defined`, `undecided`, `open question`, `open decision`, `decide whether`. Match `TBD` as a whole word.

**Task 2.** `judge.QuestionChoice` takes `Instructions` and a `Criteria` map from option to its description; an answer carries `Choice`, `Confidence` and `Probabilities` (`judge/judge.go` ~36–73). Reuse v1's request state, context bounding and secret filtering through `BuildRequest` the way `BuildRequestV2` does, then add the packets to the state and replace the questions. The decision name is `classify_v3`. Flag names are the first string-literal argument of a call to a method named `String`, `Bool`, `Int`, `Duration` or `Var` on a `flag.FlagSet` value or the `flag` package. Put fixture Go files under `classify/testdata/v3/` so they are never compiled. The seven security words are: `permission`, `sandbox`, `secret`, `redact`, `auth`, `grant`, `contain`.

**Task 3.** The bench entry is `runJudgeClassifyBench` (`cmd/batuta/judge_classify.go` ~227); the v2 path to model v3 on is `classifyBenchTasksV2` and `benchV2RecordFor` (~603–680), the measures are in `benchV2Counts` (~756–890), the outcome comes from `benchOutcome` (~334) and the journals from `readBenchJournals` (~283). Reuse them; do not copy the outcome derivation. `cmd/batuta/judge_classify_test.go` is in Scope only for a test that asserts the usage string or the accepted rubric values; no v1 or v2 test may change what it asserts about v1 or v2 output. A judge error other than `answer_mismatch` with a usable answer leaves every asked question `unavailable`, and J equals C. The bench tests use a local HTTP test server.

**Task 4.** `calibrate` is a form of `judge classify`, dispatched in `runJudgeClassify` (`cmd/batuta/judge_classify.go` ~75) beside `bench`. It reads only the file given by `--run`. The record type is the one task 3 defines; the summary object at the end of a bench run is skipped. Measures are computed exactly as in the bench, from the same functions.
