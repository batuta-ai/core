**Task 2.** Files: `review/spec.go` (`SpecRule` carries `Proof`; `RunSpecSweep` runs one session for every rule; `parseSpecResults` requires one result per rule, in order), `review/prompt.go` (`BuildSpecPrompt` prints `Proof:` lines), `cmd/batuta/main.go` (`runReview`: rules are loaded around line 658, cohorts run around line 725, then `RunSpecSweep`, then the `WorktreeState` comparison at line ~737 fails the review when the tree changed). Design: add `review.RunSpecProofs(ctx, root, rules, shell gates.ShellRunner) ([]SpecResult, []SpecRule, error)` that runs `gates.Proofs` on the rules with a non-empty `Proof` (one `gates.Criterion` per rule) and returns their `SpecResult`s (`satisfied` on pass, `violated` otherwise, `Path` = `proof: <command> exited <code>` or `proof: <command> could not run: <error>`) plus the remaining arrow-less rules. In `runReview`, with `--spec`: run the proofs first, right after the baseline `WorktreeState` is taken and before lint and cohort sessions; take the state again and, when it differs, return `review: proof of <id> changed the source tree: <paths>` (the same message shape as the existing tree-change error); then run cohorts, then `RunSpecSweep` with only the arrow-less rules (an empty list means no session, `Covered: true`); merge proof results and sweep results back into the plan's rule order before `BuildReport`. The shell runner is `gates.NewShellRunner(timeout)` with the review session timeout. `BuildSpecPrompt` no longer prints `Proof:` lines (it only receives arrow-less rules). `docs/review.md`, section "Spec conformance and linter overlap": one paragraph on the split (proof-backed criteria run through the gates in the reviewed tree, read-only sweep for the rest, a proof that changes the tree fails the review). Tests use the existing fakes in `cmd/batuta/main_test.go` (`TestReviewRefusesTreeChange` shows how a tree change is simulated) and `review/spec_test.go` (`TestSpecSweepVerdicts`).
