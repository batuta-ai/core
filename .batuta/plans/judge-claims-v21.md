## Decisions and context

Go standard library only, frozen exported signatures except additions named here, conventional commits, tests against httptest and fake judges only, no secrets. Read `.batuta/judge-benchmark.md` ("Version 2 replay") and `.batuta/judge-research.md` sections 7 and 8 first.

**Task 1.** `gates.Verdict` gains `Paths []string `json:"paths,omitempty"``; `Scope` fills it with every changed path (managed paths included, as slash paths) on both outcomes; nothing else in the verdict changes so existing assertions on `Signal`/`Detail` hold. In `loop/attempt.go` nothing changes: the report already carries the scope verdict into `gates_reported`. In `cmd/batuta/judge.go` the replay's changed-path resolution order is scope.paths → `git diff --name-only <base_sha> <commit>` using the `candidate_recorded` detail (`commit`, `evidence.base_sha`) → `git diff --name-only <base_sha> <sha>` using `worktree_snapshotted` (`sha`) → unknown. Run git through the existing `publication.CommandRunner` used elsewhere in the command, read-only, in the workspace. Print `changed_paths=<n>` or `changed_paths=unknown` on the replay line after `claims=`.

**Task 2.** In `loop/claims.go`, `ExtractClaims` gains a `known func(path string) bool` input (built by the caller from the tree listing, changed paths and Scope globs through `gates.InScope`); a token becomes a path claim only when `known` returns true. Criterion claims: parse `n`, set `Criterion = n`, `Text = criteria[n-1].Text` when in range (drop the claim when out of range). In `SettleClaims` build `Evidence` as "proof: <signal>; verifier: <line>" from whatever exists. In `loop/judgment.go` the caller provides `known` from `ClaimEvidence` plus a tree listing obtained with `git ls-files` in the worktree (live) or from the candidate commit (replay, through the same resolution as task 1); claims whose evidence is empty are set `unverifiable` with `Source: code` and are not sent.

**Task 3.** This task runs with the real judge: the executor sets the three keys from the conducting environment only if they are already present; if `batuta judge probe` reports `key_missing`, write the raw file with the `unavailable` lines the replay prints and say so in the benchmark section instead of inventing numbers. Commands, from the repository root with the freshly built binary: `go build -o /tmp/batuta-v21 ./cmd/batuta`, then for each journal under `.batuta/journal/` whose name starts with `research-ladder-`, `silent-proofs-`, `cursor-models-ansi-`, `judge-package-`, `judge-vercel-auto-`, `judge-claim-evidence-`, `judge-polish-`, `judge-claims-v2-`, `judge-claims-v21-` run `/tmp/batuta-v21 judge replay --journal <path>`, and for the two skills journals `../skills/.batuta/journal/research-ladder-*.jsonl` and `hidden-scope-rule-*.jsonl` add `--runs ../skills/.batuta/runs`; append every line verbatim under a `## <repo> <journal file>` header. The benchmark section quotes counts from that file and nothing else.
