# Plan — Stop processes left inside a removed worktree
<!-- inputs: profile.md@sha256:e18a00765937 routing.md@sha256:bdb31fda5c7d -->

**Goal:** When batuta removes one of its worktrees (loop integration or abort, replacement of a leftover tree, `batuta loop --prune --apply`), it first stops the processes whose working directory is inside that worktree, best effort per OS, and says which ones it stopped. This is the last part of finding 4.4 (c) of the Tempo retrospective (`.batuta/feedback/2026-09-21-tempo-mvp-triage.md`): three `next dev` servers started in removed worktrees were still alive six days later.
**Created:** 2026-10-14 · **Status:** approved

## Decisions and context

Finding 4.4 (c) had two parts. Orphaned worktrees shipped in core#170 (`batuta loop --prune`). This plan covers the second part: processes such as a dev server that an executor started in the background and that outlive the attempt. The executor's process group is already killed when its context ends (`publication/command_unix.go`), but a server started with `&`, `nohup` or `setsid` leaves that group and survives a normal exit.

Removal sites in scope: everything that goes through `GitProvider.Remove` (`worktree/git.go`): `Runner.removeWorktree`, which `loop/attempt.go`, `loop/settle.go` and `loop/report.go` call, `GitProvider.addAt`, which removes a leftover tree before adding its replacement, and `loop.Prune`. The disposable preflight worktree of `integration/git.go` is out of scope: no executor runs there.

Matching is by working directory only. A process counts when its working directory is the worktree root or below it, after symlinks are resolved on both sides (macOS reports `/private/var/...` for `/var/...`). Open files and command-line arguments do not count. Only processes the current user can see are found; the executors run as that user.

Safety floor: a scan target must be an absolute, clean path with at least three elements that is neither the file-system root, nor the user's home, nor a strict ancestor of the home, else `ErrUnsafeProcessTarget`. The check runs twice, on the path as given and on its resolved symlink target, so a clean path that links to the home directory is refused. There is no rule about the conductor's working directory: a conductor or shell inside the worktree is handled by the ancestor exclusion below. `StopProcesses` repeats the safety floor and the ancestor exclusion before any signal, so a direct caller cannot bypass them. Everything else inside the worktree is stopped, an interactive shell included: a shell in a directory about to be deleted has nothing left to work on.

Ancestor exclusion: the calling process and every ancestor of it are never signalled. The ancestor set is built by walking parent PIDs up from `os.Getpid()` through a parent lookup that reads each process on its own (Linux `/proc/<pid>/stat`, macOS `sysctl kern.proc.pid` through `golang.org/x/sys/unix`), never from the scan result, so a partial scan or a chain that leaves the worktree and re-enters it cannot hide an ancestor. When the walk cannot reach PID 1 (a lookup error), the operation fails closed: no process is returned for stopping and no signal is sent.

`Remove`, `StopInside` and `ProcessesIn` share two stricter rules before any scan. The path, resolved canonically, must be a direct child of an allowed home: `Home`, `RepositoryHome(Root)` or `CacheHome(Root)`, each resolved through symlinks too. And git must list it as a worktree of `Root` (`git worktree list --porcelain`, the source `GitProvider.Managed` already reads). A directory that fails either rule gets no scan; `Remove` passes it to git as before.

Accepted risk: an editor, a terminal or another agent session whose working directory is inside a batuta worktree is stopped too, SIGKILL included after the grace period. Batuta worktrees are batuta's own; the docs say so and name `--keep-worktrees` as the way to keep a worktree and its processes.

Process identity is PID, command, working directory and start time. Linux takes the start time from `/proc/<pid>/stat` field 22 (clock ticks); macOS takes it from `sysctl kern.proc.pid` (`p_starttime`, microseconds), together with the parent PID and the zombie state, so macOS needs no `ps`. Before each signal the process is inspected again and all four must match. On Linux the stopper opens a pidfd (`pidfd_open`) before the recheck and signals through it (`pidfd_send_signal`), so a PID reused after the recheck cannot be hit; a kernel without pidfd falls back to the macOS behaviour. On macOS a window remains between the last recheck and `kill`: a process that ends and has its PID reused inside that window, with the same command, working directory and start microsecond, would be signalled. That residual PID reuse risk is accepted and documented. The grace period between SIGTERM and SIGKILL is 3 seconds. A process counts as ended when it is gone or a zombie. Every liveness check in this plan uses the same helper, so a zombie never reads as alive.

Seams, two interfaces so earlier fakes never break: `worktree.ProcessScanner` with `Inside(ctx, dir) ([]Process, error)`, and `worktree.ProcessStopper` with `Stop(ctx, dir string, procs []Process, grace time.Duration) ([]StoppedProcess, error)`. `GitProvider.Processes` and `GitProvider.Stopper` hold one each; nil means the OS implementation. `GitProvider.OnProcessesStopped func(path string, stopped []StoppedProcess, err error)` is an optional callback, called only when something was stopped or skipped, or an error occurred. `loop.Options.Processes` and `loop.Options.Stopper` reach the provider the runner builds at `loop/runner.go:442`, the same way `Options.Runner` already does; `PruneOptions.Processes` and `PruneOptions.Stopper` reach the provider `Prune` builds. Adding struct fields changes no exported function signature.

The repository convention applies: `cmd/batuta` builds for linux, darwin and windows, and no package it imports uses bare `syscall`. `golang.org/x/sys`, already in the module graph as an indirect dependency, becomes direct and is used only in `_linux.go` and `_darwin.go` files. Tag scheme: `_linux.go` and `_darwin.go` name suffixes for the per-OS code, `//go:build linux || darwin` for the shared Unix stopper and for every test that starts a real process, `//go:build !linux && !darwin` for the unsupported defaults. An untagged file is one with no `//go:build` line and no `_linux`, `_darwin` or `_windows` name suffix; untagged files use only `os` and the package's own types. Tests that start `sleep` or `sh` always kill their children in `t.Cleanup`, and take temp dirs from the existing `tempDir(t)` helper in `worktree/git_test.go`, which resolves symlinks.

Native runs: the loop runs on macOS, so the darwin tests run natively in its proofs; core CI runs `ubuntu-latest`, so the Linux-tagged tests run natively on the pull request. Neither environment runs both, and no proof claims to.

**Task 1.** Types: `type Process struct { PID, PPID int; Command, Cwd string; Start time.Time }`, `ErrProcessScanUnsupported`, `ErrUnsafeProcessTarget`, `type PartialScanError struct { Warning string }`, the `ProcessScanner` interface and the unsupported scanner, all in `processes_parse.go`, a file without build tags, together with the parsers and the ancestor walk, so every test of this task runs on every host. `insideWith(ctx, env, dir)` takes a small `insideEnv` struct: the scanner, the home directory, the caller PID and a parent lookup `func(pid int) (int, error)`. Tests fill it directly and stay parallel, with no `t.Setenv` or `chdir`. This task declares no default scanner and no `ProcessesInside`; task 2 adds both.

**Task 2.** `processes.go` declares `ProcessesInside(ctx, dir)`, which calls `insideWith` with the OS scanner, `os.UserHomeDir()`, `os.Getpid()` and the OS parent lookup; the defaults are declared once per platform file. Linux reads `/proc/<pid>/cwd` with `os.Readlink` and `/proc/<pid>/stat` through task 1's parser; the walk over `/proc` runs under a 5-second context deadline, checked between processes. macOS has no `/proc` and the release binaries are built without cgo, so it runs `/usr/sbin/lsof -n -P -a -d cwd -F pcn` under a 5-second timeout for the working directories, and `unix.SysctlKinfoProc("kern.proc.pid", pid)` for parent PID, start time and state. The lsof path is a package variable so `processes_darwin_test.go` can point it at a script that sleeps. lsof exits 1 when it cannot read some processes: keep the records it printed and return them with a `*PartialScanError`; callers act on the processes and report the warning. Every other OS, Windows included, uses the unsupported scanner: reading another process's working directory on Windows needs its PEB through `NtQueryInformationProcess`, which is out of proportion here. The ancestor test uses the test binary's own helper mode (`TestMain` checks an environment variable), started by a `sh` whose working directory is inside `dir`.

**Task 3.** `type StoppedProcess struct { Process; Signal, Reason string }`, `Signal` being `TERM`, `KILL` or empty; an empty `Signal` means skipped, with the reason. Injectable pieces: a signaller, the parent lookup from task 1, and an inspector `Inspect(pid) (command, cwd, state string, start time.Time, err error)` used for the recheck and for liveness. The macOS inspector reads the working directory with `lsof -p <pid> -a -d cwd -F n` under the same timeout. The Linux signaller holds the pidfd from before the recheck until the process ends. The tests count calls on fakes for the unsupported, recheck and guard cases.

**Task 4.** `ProcessesIn(ctx, path) ([]Process, error)` checks the allowed homes and the git registration, then scans; it never signals. `StopInside(ctx, path) ([]StoppedProcess, error)` checks the same rules, scans and stops, and calls `OnProcessesStopped`. `Remove` calls `StopInside` for a path that passes the rules, then runs `git worktree remove`; its own signature does not change. A scan or stop error never makes `Remove` fail; it goes to `OnProcessesStopped`. A `*PartialScanError` stops the processes found and still reaches the callback as the error.

**Task 5.** Only `StopInside` stops: `Runner.removeWorktree` adds no scan of its own, so every stop goes through one path, the `OnProcessesStopped` callback. The cost is that the scan and the grace period run while `worktreeMu` is held, up to 5 seconds of scan plus 3 seconds of grace per removal; that is accepted because removals are already serialized by that lock, and a worktree with live processes is the rare case. The runner sets `OnProcessesStopped` once and accumulates the stopped processes per delivery under its own mutex. One line per entry with `TERM` or `KILL` goes to `r.out`: `<task> stopped pid <pid> (<command>) in <worktree root> with SIG<signal>`; a skipped entry prints a warning with its reason instead. The same lines are appended at once to the run trail of the task that owns the worktree (`trailPath` in `loop/report.go`), so they survive an interrupted run. The fake executor starts the background process with `nohup sleep 30 >/dev/null 2>&1 &` and writes the PID to a file outside the worktree for the test to check.

**Task 6.** Record order, from `loop/report.go`: `completeFinalization` calls `cleanFinalization`, which removes the remaining worktrees, then `checkpointFinalization`, and only then `recordFinalization` appends the terminal record. `stopped_processes` is a field of `terminalDetail`, so a finalization stop is in the checkpoint written after cleanup and resume restores it through the existing finalization recovery. The `cleanup` record in `loop/settle.go` gets the same field, taken from the callback for that worktree before the record is written. Only `TERM` and `KILL` entries are journaled. Accepted gaps: a finalization stop interrupted before that checkpoint, and an attempt-level stop of a run interrupted before finalization, are kept in the run trail only; persisting them in the journal would need a new record kind, and a record kind written next to a terminal record already broke `pruneOwned` (core#170, presence takeover). The tests of this task use fake scanners and stoppers, so they live in the untagged `loop/worktree_processes_test.go`. `routing/signatures_test.go` holds `var _ func(*DeliveryGraph, <exact parameter types>) <exact result types> = (*DeliveryGraph).SettleWave` and the same for `RecordFailure` (`routing/graph.go`).

**Task 7.** The dry run only reads: it calls `ProcessesIn` for each orphaned entry and never a stopper. `Apply`, after `pruneStillOrphan` confirms the entry, calls `StopInside`, then `Park`, then `Remove`, whose second scan then finds nothing and calls no callback. That second scan is accepted: it keeps one stop path and costs one more scan only for entries `--apply` removes. The provider's `OnProcessesStopped`, set by `Prune`, fills `PruneEntry.Processes` and turns errors into `PruneReport.Warnings` (`loop/prune.go:40`). A missing worktree directory has nothing to scan. `PruneEntry` gains `Processes []worktree.StoppedProcess` with `Signal` empty in a dry run.

**Task 8.** Exit codes follow the profile: a dry run that lists processes exits 0, since listing is success. `TestLoopDocWorktreeProcesses` reads `docs/loop.md` from the repository root and checks the strings named in its criterion inside the `## Worktree processes` section. `TestLoopPruneHelp` already exists in `cmd/batuta/main_test.go`; extend it.
