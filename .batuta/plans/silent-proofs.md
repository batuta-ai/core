# Plan — proofs before "already satisfied"
<!-- inputs: profile.md@sha256:e18a00765937 routing.md@sha256:d8b592b68c43 -->

**Goal:** Stop the loop from declaring a silent attempt "already satisfied on the base" when the task's proof commands do not all pass on that base. Today the silent path skips the proofs and trusts the read-only verifier alone, which let an executor that wrote nothing and a cheap verifier that answered DONE close two tasks whose proofs would have failed.
**Created:** 2026-09-20 · **Status:** approved

## Decisions and context

Go standard library only, frozen exported signatures, conventional commits, no journal schema change. The gates report already has a `Proofs []Verdict` field and `gates.Proofs(ctx, shell, dir, criteria)` already runs proof commands in a worktree; the silent branch of `runAttempt` in `loop/attempt.go` (the `else if silent && report.Finished.Pass` arm) simply never calls it and passes the empty `report.Proofs` to `r.verify`.

**Task 1.** In the silent arm, run `report.Proofs = gates.Proofs(ctx, r.shell, ac.worktree.Root, criteria)` after the tests and before the verifier, and require every proof verdict to pass in addition to `verdict.Pass && report.Tests.Pass` before recording `blockerAlreadySatisfied`; when a proof fails, keep the existing fall-through to the `tree` failure verdict so the attempt is retried with feedback naming the failed proof, exactly as a non-silent attempt with a failed proof is. Do not change the non-silent arm, the verifier prompt, `recordBlocked` or the journal kinds. The new test lives beside `TestLoopAlreadySatisfiedOnlyWhenWorktreeEqualsBase` in `loop/loop_test.go` and reuses its fixture: a task whose criterion carries a proof command that exits non-zero on the base while the fake verifier answers DONE and the profile test passes; assert no `blockerAlreadySatisfied` failure record, a gates record with at least one failing proof verdict, and that the run does not end `StateDone` on that attempt. Extend the existing satisfied scenarios only if a shared helper makes both tests shorter. In `docs/loop.md`, extend the sentence that describes the silent attempt so it lists tests, proofs and verifier on the base.
