## Decisions and context

User approved integrating supervision into the normal loop experience and explicitly answered yes to blocking subsequent phases when final review finds problems. Implement this direction, not a new scheduler, external daemon or installed service. Existing runner is sole execution owner; use existing observer, durable cursor, immutable review artifacts, explicit continuation policy and budget/ownership guards. External watchdog evolution is deferred to process availability only. Native/ACP qualification, goals per CLI, token-savings pilot and SVG/article are separate work.

Base is core origin/main 1257ece (v1.1.0-beta.22), which already contains the supervisor and review recovery fixes. Preserve all those regressions. The normal CLI currently calls Runner.Run and the standalone --supervise branch sets executable-backed review; reuse that machinery. RunRoadmap currently advances after StateDone, and report.go ticks phases before review: a transient CLI error cannot be the durable gate. Read the owning code before choosing the narrowest persistent representation; avoid a duplicate journal or acceptance framework.

Interpret review outcome precisely: an intact complete SHIP report clears only the progression check; it is not a conductor acceptance declaration or Git approval. Any FIX_BEFORE_SHIP/REWORK, missing report, failed job, partial coverage or uncertain launch blocks until explicit valid operator judgment or a separately verified correction produces eligible current evidence. Do not manufacture SHIP, auto-accept findings, relaunch uncertain review jobs, or silently reset the existing review attempt budget. Preserve legacy library behavior when supervision is absent; new normal CLI executions enable it. If additional persistence owners outside Scope are necessary, stop and report the exact additional paths before editing.

**Task 1.** Add deterministic tests using existing immutable-review and temporary Git fixtures. Persist identity before bookkeeping can advance a phase; test crash/restart after implementation completion, after review launch, after an adverse report, and after judgment. Explicit accept/reject judgment must carry nonempty rationale and exact evidence digest and validate delivery/job/report integrity plus no live owner. Same valid decision replay is idempotent; tampering, wrong delivery, stale evidence and ambiguous ownership cannot release a gate. Reuse current correction ancestry when safely supported; do not infer that any later successful delivery fixes a parent's findings. If no verified correction relationship exists, preserve the block and provide explicit judgment recovery rather than inventing a link. Do not reinterpret all old archived deliveries as newly review-blocked.

**Task 2.** Observe passively while Runner.Run owns the delivery; final review and authorized continuation may run only after ownership release. Join goroutines/processes on every exit path and preserve cancellation/uncertainty semantics. The default cursor must be deterministic, private and outside .batuta/journal. Resume and roadmap discovery must find a review-pending delivery even when implementation is terminal/archived. No busy LLM polling, duplicated retries or unbounded passive observer after waiting-input, blocked or max-waves. Tests inject deterministic executors/reviewers; do not call real model CLIs.

**Task 3.** Normal execution must fail visibly if required review cannot run; never silently fall back to unreviewed success. Keep standalone --supervise attachment and established nonexecuting commands. Extend existing flags coherently to expose explicit digest-bound judgment with rationale; document exact CLI usage and nonzero review-pending state, separating it from implementation done. Existing --policy remains opt-in; starting a supervised loop grants no new permission to answer questions or correct findings. Retain stdout contract and separate worker logs from structured observer reports. No release tooling, dependency changes, global installation or frozen public routing signatures. English documentation with existing Portuguese README mirror. Work test-first and preserve test hygiene; do not relax assertions or skip tests to force green.
