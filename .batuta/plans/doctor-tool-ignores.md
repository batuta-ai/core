# Plan — `batuta doctor` reports tools that would scan `.batuta/`
<!-- inputs: profile.md@sha256:e18a00765937 routing.md@sha256:bdb31fda5c7d -->

**Goal:** `batuta doctor` finds the project's test runners, linters, formatters and type checkers configured at the workspace root or invoked by its `package.json` scripts, with TypeScript read only from the root `tsconfig.json`, and says, for each one, whether it keeps out of `.batuta/`: already ignored, not needed, missing (with the exact entry to add) or unknown. It reports only and never edits a file; `/batuta-init` does the patching. This is the last open part of finding 4.4 of the Tempo retrospective (`.batuta/feedback/2026-09-21-tempo-mvp-triage.md`): vitest and eslint scanned `.batuta/**` and failed the project's gate on orchestrator files.

## Decisions and context

Finding 4.4 had three parts. (b) worktrees outside the repository shipped in core#170, (a) `/batuta-init` patching tool ignore lists shipped in skills v0.16.0 (skills#78), and (c) cleanup of orphaned worktrees and of their processes shipped in core#170 and core#174. This plan covers the remaining piece of (a): the triage asks that `batuta doctor` detect the same tools too, so a project set up before skills v0.16.0, or one whose configs changed later, is told what to add.

Source of the tools, config files and entries: `skills/batuta-init/references/tool-ignores.md` in batuta-ai/skills v0.16.0. The hints in the table below are the exact strings, and the tests assert them in full. Two rows differ from that reference on evidence gathered for this plan, and the skills reference should follow in its own change: TypeScript (TypeScript 5 `tsc --listFilesOnly` on a fixture with `src/a.ts` and `.batuta/wt/b.ts` lists only `src/a.ts` for no `include` and for `include: ["./**/*"]`, and lists both only for `include: [".batuta/**/*", "src"]`, so `tsc` wildcards skip dot-directories and only an explicit `.batuta` path needs an `exclude`), and Biome v2 (a `files.includes` list with only negated patterns selects no file, so a new list needs `"**"` first). The reference says the ignores are needed with either `Worktree-home`, since run trails, review snapshots and journals stay in `.batuta/` either way; so the check runs whenever the workspace root has a `.batuta/` directory, whatever the profile says, and does not read the profile.

Tool behaviour checked against each tool's documentation on 2026-10-18 for this plan, so no task needs network access. Biome configuration reference (https://biomejs.dev/reference/configuration/): `files.includes` patterns "are evaluated in order, and the last matching pattern wins", a list of only exclusions selects no files, `!!` is a force-ignore in `files.includes`, only `node_modules/` is ignored by default, and VCS ignore files apply only with `vcs.useIgnoreFile`. pytest configuration reference (https://docs.pytest.org/en/stable/reference/customize.html): the precedence below, `pytest.toml` and `pytest.ini` match even when empty, `pyproject.toml` needs `[tool.pytest]` or `[tool.pytest.ini_options]`, `pytest.toml` since pytest 9.0. ESLint ignore reference (https://eslint.org/docs/latest/use/configure/ignore): an `ignores` key is global only in an object with no other key besides `name`, `globalIgnores()` from `eslint/config` adds global ignores, defaults are `**/node_modules/` and `.git/`, and `.gitignore` is not read unless the config uses `includeIgnoreFile`. Prettier ignore reference (https://prettier.io/docs/ignore): Prettier reads `.prettierignore` and the `.gitignore` of the directory it runs from, and ignores `node_modules` and VCS directories by default. If an executor finds a tool behaving otherwise, it stops and reports instead of changing the table.

Discovery reads only files at the workspace root: the configs named below, `package.json`, `.eslintignore`, `.prettierignore` and `.gitignore`. The one exception is a relative TypeScript `extends`, which may point to a file in a subdirectory of the root. `tsconfig.*.json` variants are not discovered; only `tsconfig.json` is. A package config inside a monorepo workspace does not walk the root and needs nothing. The workspace root is the directory `doctor` already resolves through `workspaceRoot(--workspace)`, the current directory by default.

Detection never evaluates code. JavaScript and TypeScript configs are lexed, not run: comments are stripped and only string literals, object keys and call names count, so a comment that mentions `.batuta` proves nothing. The lexer knows strings, templates with nested `${...}`, comments and regex literals (a `/` starts a regex at the start of the source, after one of `( , = : [ ! & | ? { ;`, or after the keywords `return`, `typeof`, `case`, `in`, `of`, `new`, `delete`, `void`, `throw`, `instanceof` and `yield`; after `)`, `]`, `}`, an identifier or a number it is division). An unterminated token is an error and the config's finding is `unknown`; a source the lexer misreads therefore surfaces as `unknown`, never as `ignored`, and that is accepted. A `.batuta` literal counts as `ignored` only when it sits inside the value of the tool's ignore key, found with `keyLiterals`: a literal elsewhere, such as in `test.include`, may select `.batuta` instead of skipping it, so it gives `unknown`. Doctor does not check which object the key belongs to beyond the ESLint rule below, and an ignore list spread from a shared preset is invisible to it; both limits are stated in `docs/doctor.md`: the report is advice, the project's gate is the proof. JSON, JSONC, YAML (`gopkg.in/yaml.v3`, already a direct dependency), INI and TOML files are parsed.

Statuses, the same strings in text and JSON: `ignored`, `not_needed`, `missing` and `unknown`. No status changes the exit code of `doctor`.

Decision table. "Literal" means a string literal of the stripped source contains `.batuta`. "Keyed literal in K" means such a literal inside the value of a key named K; "stray literal" means a literal and no keyed literal in the row's keys. For the `jest` key of `package.json`, already parsed as JSON, a keyed literal is a string containing `.batuta` in the array under that key, and a stray literal is any other string containing `.batuta` anywhere in the `jest` object. A Vitest literal means a string literal equal to `vitest` or starting with `vitest/`. "Named directory" means a value that, after dropping a leading `./`, is not empty, is not `.`, is not absolute, has no `..` segment, and whose first segment has no `*`. A config found by more than one name gives one finding per file.

Ignore-file lines (`.eslintignore`, `.prettierignore`, `.gitignore`): trim the line; skip it when empty, starting with `#` or starting with `!`; it matches when, after dropping a leading `/`, a leading `**/`, a trailing `/` and a trailing `/**`, it equals `.batuta`.

Biome version: from the `$schema` URL of the config (`/schemas/<version>/`), else from the `@biomejs/biome` entry of `dependencies` or `devDependencies` in `package.json`: strip leading `^`, `~`, `>`, `<`, `=`, `v` and spaces and read the major number; anything else is unknown. Doctor evaluates Biome v2 patterns in order, the last matching pattern winning. A pattern, after dropping a leading `!!` or `!` and a leading `./`, matches `.batuta` when it is `**` or `**/*`, or when its first segment is `.batuta`, or when it starts with `**/.batuta`; any other pattern, such as `src/**`, does not match it.

TypeScript `extends`: a string or an array; an entry starting with `./` or `../` is a relative config, read with or without the `.json` suffix, at most five files in all, its path resolved through symlinks and required to stay inside the resolved root. `include`, `files` and `exclude` each come from the nearest config that sets them. Each entry is resolved against the directory of the config that sets it into a path relative to the root, then cleaned. An `include` or `files` entry selects `.batuta` when that path's first segment is `.batuta` or it starts with `**/.batuta`. An `exclude` entry covers `.batuta` when that path, after dropping a trailing `/**/*` or `/**`, is `.batuta` or `**/.batuta`. A package `extends` (any other entry) is not read, and the local file decides: `tsc` wildcards skip dot-directories, so a base could only reach `.batuta` by naming it, and published bases such as `@tsconfig/*` set no `include` or `files` naming it. Reporting `unknown` for every package base would bury the report in noise; `docs/doctor.md` states this limit.

pytest values: INI `norecursedirs` and `testpaths` are split on whitespace across continuation lines, each entry unquoted; TOML takes a list or a whitespace-split string. An entry matches `.batuta` when `path.Match(entry, ".batuta")` holds, the basename match pytest does with fnmatch, so `.*`, `*.batuta` and `.b*` match and `.batuta-old` does not. Precedence: pytest uses the first of `pytest.toml`, `.pytest.toml`, `pytest.ini`, `.pytest.ini` (each one by presence, even when empty), `pyproject.toml` with `[tool.pytest]` or `[tool.pytest.ini_options]`, `tox.ini` with `[pytest]`, `setup.cfg` with `[tool:pytest]`. An empty or sectionless `pytest.toml` or `pytest.ini` is the config pytest uses and has no `norecursedirs`, so it is `not_needed`.

Script detection reads only the root `package.json` `scripts` values, splitting each on whitespace and on `&&`, `||` and `;`, ignoring quoted arguments, and matches a word equal to `vitest`, `jest`, `prettier`, `eslint`, `biome` or the pair `playwright test`, also after `npx`, `pnpm exec`, `yarn` or `bunx`. Task 3 writes it in `ignores/scripts.go`, and tasks 4 and 5 reuse it.

**Tasks 1–7.** New package `ignores` at the repository root, beside `worktree` and `review`. API: `func Check(root string) ([]Finding, error)` with `type Finding struct { Tool, Config, Key, Status, Hint string }` and JSON tags `tool`, `config`, `key` (omitted when empty), `status`, `hint` (omitted when empty); `Key` names the `package.json` key a finding came from (`jest`, `eslintConfig`, `prettier`, `scripts`). Status constants `Ignored`, `NotNeeded`, `Missing`, `Unknown`; `var Tools = []string{"biome", "eslint", "jest", "playwright", "prettier", "pytest", "typescript", "vitest"}`. Detectors: `type detector struct { tool string; run func(root string, pkg *packageJSON) ([]Finding, error) }`, an unexported `check(root string, detectors []detector) ([]Finding, error)` that does the work, and `Check` calling `check(root, defaultDetectors)`. `defaultDetectors` is a package-level slice in `ignores.go` that tasks 3–7 each extend and that no code or test mutates; tests call `check` with their own list, so `t.Parallel()` shares no state. `check` reads and parses the root `package.json` once and hands every detector the parsed value (nil when missing or invalid); an invalid `package.json` is reported once under the tool `package.json`. A detector error becomes an `unknown` finding for its tool, with the error as hint. `check` returns an error only when the root cannot be read or `.batuta` is not a directory. Standard library plus `github.com/pelletier/go-toml/v2` and `gopkg.in/yaml.v3`, both already direct dependencies; no new module, and the JSONC parser and the JavaScript lexer are written in the package. Config extensions: `.js`, `.mjs`, `.cjs`, `.ts`, `.mts`, `.cts`; Jest also `.json`; ESLint legacy `.eslintrc` (JSONC, else YAML), `.json`, `.js`, `.cjs`, `.yaml`, `.yml`; Prettier rc files are only detected, never parsed. Tests are table-driven with `t.Parallel()` and take fixture directories from a package-local `tempDir(t)` helper in `ignores/helpers_test.go` that resolves symlinks, as the profile requires. Task 6 adds to that file a `symlink(t, target, link)` helper that calls `t.Skip` when the system refuses to create the link, as on Windows without the privilege.
