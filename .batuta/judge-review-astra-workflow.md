## Proposed decision architecture

The following is a proposal, not a description of implemented Jev capabilities.

### Order: establish facts, isolate uncertainty, then spend judgment

**First, make criterion coverage explicit.** Each criterion should have an evidence status such as `mechanically established`, `semantic review required`, `failed` or `evidence unavailable`. Do not encode “left to the verifier” as a passing result that can survive without a verifier. The current proof sentinel and lane-based dispatch predicate permit precisely that combination. ([Proof sentinel](/Volumes/Home/francisross/Projects/batuta/core/gates/gates.go:353), [dispatch](/Volumes/Home/francisross/Projects/batuta/core/loop/attempt.go:371), [reduction](/Volumes/Home/francisross/Projects/batuta/core/gates/gates.go:472).)

**Second, run deterministic rejection checks before optional semantic work.** Check execution/reconciliation, scope and applicable mechanical evidence before launching a verifier. Where failure already determines rejection, skip semantic acceptance work unless a separately justified diagnostic policy requires it. Today the verifier runs before `Decide()` without testing whether tests, scope or proofs already failed. This is a code optimisation and should receive no Jev savings credit. ([Current order](/Volumes/Home/francisross/Projects/batuta/core/loop/attempt.go:362).)

**Third, construct a bounded evidence packet for one semantic question.** Code should authenticate paths, hashes, offsets, IDs and command results. A cheaper read-only LLM may locate the relevant implementation, assertion or policy passage when deterministic retrieval cannot. Preserve exact source excerpts and unresolved dependencies. Jev then classifies the relationship among those supplied facts; it does not discover missing repository evidence. That division matches its recorded limitations and the existing scout contract. ([Jev capabilities](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-research.md:7), [scout evidence](/Volumes/Home/francisross/Projects/batuta/skills/skills/batuta/references/scout.md:30).)

**Fourth, escalate by the missing capability.**

- Missing or ambiguous repository facts → repository-reading verifier/reviewer.
- Contradictory instructions, scope changes, new permissions or unresolved product choices → conductor/human.
- Malformed, unavailable or uncertain Jev answer → retain the existing baseline decision.
- Positive, sufficiently validated contradiction → annotation, additional scrutiny or an authorised veto; never a pass.

These boundaries preserve the documented rule that Jev cannot approve, answer questions or widen scope, and the supervision requirement that prose never supplies authority. ([Judge contract](/Volumes/Home/francisross/Projects/batuta/core/docs/judge.md:398), [supervision boundary](/Volumes/Home/francisross/Projects/batuta/core/docs/loop-supervision.md:173).)

### What should never be delegated to Jev

Keep proofs, path/scope membership, counts, hashes, framing/schema validation, coverage arithmetic, reset-time arithmetic, eligibility, budgets, dependency admission, Git ancestry and ownership checks in code. Those are already deterministic responsibilities; the research also records counting, dates and multi-hop reasoning as weaknesses. ([Inventory](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-research.md:29), [limitations](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-research.md:11).)

Do not give Jev authority over permission grants, uncertain-work replay, scope expansion, SHIP acceptance or publication. Do not ask it to establish whole-repository behavioural correctness, root cause or architecture quality from a short preview. Repository-reading agents and the human retain those responsibilities. ([Dispatch uncertainty](/Volumes/Home/francisross/Projects/batuta/core/docs/dispatch.md:193), [approval boundary](/Volumes/Home/francisross/Projects/batuta/core/docs/loop-supervision.md:264), [recorded capability limit](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-research.md:84).)

Static lane-model choice and the current broad behavioural-claim checker are **not worth further routine Jev calls now**. Preserve code settlement; revisit either model application only with a new, bounded experiment that addresses the earlier reviews’ evidence requirements. ([Prior routing conclusion](/Volumes/Home/francisross/.claude/jobs/ba13ca57/tmp/judge-review-astra-lanes.md:49), [claim benchmark](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-benchmark.md:150).)

### How this reduces expensive LLM work

**Verifier:** First eliminate sessions on already-rejected attempts. Then reduce investigation time with authenticated, criterion-specific evidence and explicit unresolved questions. A validated Jev veto could eventually reject a clearly defective attempt before its verifier, but false vetoes must be charged for the worker retry they cause. A favourable Jev answer must still reach every verifier required by the baseline. The **58-second figure is a 14-run sample**, not a universal task cost. ([Current ordering](/Volumes/Home/francisross/Projects/batuta/core/loop/attempt.go:362), [measurement](/Volumes/Home/francisross/Projects/batuta/core/WORK.md:15).)

**Final review:** Preserve manifest coverage and repository access. Use Jev to identify a finding’s applicable rule or a possible contradiction, with a cheap reader supplying exact evidence where necessary. This can shorten conductor adjudication and prevent misguided fix cycles. It cannot suppress a “noise” finding automatically, mark a cohort covered or substitute an empty finding list. Review already removes proof-backed criteria from the semantic sweep and supports incremental rounds; supervised final delivery review deliberately uses `--full`. ([Spec optimisation](/Volumes/Home/francisross/Projects/batuta/core/docs/review.md:89), [incremental state](/Volumes/Home/francisross/Projects/batuta/core/docs/review.md:109), [supervised full review](/Volumes/Home/francisross/Projects/batuta/core/docs/loop-supervision.md:224).)

**Conductor:** Present compact decision packets: original question/finding, exact relevant evidence, Jev category, uncertainty and the existing permitted next actions. Jev supplies typed categories; code can render the packet. The conductor retains the one-line judgment and access to original evidence. This targets searching and repeated reading, rather than treating the conductor’s responsibility as removable overhead. ([Typed output](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-research.md:7), [conductor requirement](/Volumes/Home/francisross/Projects/batuta/skills/skills/batuta-review/SKILL.md:23).)

Any future cheaper-reviewer policy should be independently approved and evaluated against its baseline. Jev may add escalation to that policy; it should not silently downgrade a currently required strong reviewer.

## Way of working

### Record decision opportunities, not only outcomes

Extend the impending telemetry work around **each actual invocation**, including internal quota retries/fallbacks, verifier sessions, review cohorts and spec sweeps. Record:

- Delivery/task/execution **and invocation identity**, role, runtime/model/version/effort, transport, timestamps, exit state, cancellation and submission uncertainty.
- Original regex/mechanical result, semantic category, proposed action and action actually taken.
- Bounded separate stdout/stderr tails, truncation/redaction indicators, and retained immutable evidence references.
- Nullable provider-reported input/output/cached/total usage with provenance; phase duration, retry/review aftermath and conductor active time separately from human waiting.
- Criterion coverage, later accepted/declined findings, correction ancestry and human assistance.

This is a proposed measurement contract. The approved telemetry plan adds worker tails and usage, but its named `executor_finished` insertion point is **after** internal limit repetitions and early error/reconciliation exits. It therefore does not, by itself, capture every unclean invocation. Verifier dispatch also uses a separate result path. ([Plan](/Volumes/Home/francisross/Projects/batuta/core/.batuta/plans/executor-telemetry.md:8), [placement](/Volumes/Home/francisross/Projects/batuta/core/loop/attempt.go:279), [early exits](/Volumes/Home/francisross/Projects/batuta/core/loop/attempt.go:318), [verifier dispatch](/Volumes/Home/francisross/Projects/batuta/core/loop/attempt.go:695).)

For every Jev decision, retain the exact redacted packet, question/rubric version, returned model, full distribution, unavailable/abstention reason, threshold, policy result and timings. Keep sensitive bodies in bounded private artifacts, with references in the journal. A digest without retained content is insufficient: **41 source attempts lost their diff**, and earlier live/replay inputs differed materially. ([Lost evidence](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-benchmark.md:252), [live/replay mismatch](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-benchmark.md:73).)

Also sample clean successes and non-triggering cases. Unclean-only telemetry cannot reveal all false successes or estimate false alarms on normal traffic. The planned clean-session omission makes this a separate sampling requirement. ([Telemetry scope](/Volumes/Home/francisross/Projects/batuta/core/.batuta/plans/executor-telemetry.md:10).)

### Establish independent ground truth

Label the **atomic relation and the appropriate action separately**. For example, “environment-only explanation” does not imply “safe to accept this task”; “finding contradicts a supplied rule” does not establish that the rule is current or that the finding is otherwise false.

Have a competent reviewer label cases without seeing Jev’s answer. Have a second reviewer adjudicate disagreements and all cases proposed for automatic action; retain `insufficient evidence` rather than forcing labels. For behaviour questions, inspect the complete relevant implementation and tests. A candidate, passing suite or generated “true” sentence is not sufficient ground truth—the earlier review established those weaknesses. ([Ground-truth critique](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-review-astra.md:27).)

Keep all attempts, variants and borrowed material from the same delivery in one partition; add time/provider-separated tests where appropriate. Preserve hard negatives containing the same vocabulary as positives, plus mixed and genuinely indeterminate cases. This addresses the earlier attempt-level leakage and easy-negative dilution. ([Split/mixture critique](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-review-astra.md:84).)

### Freeze the whole policy before measuring

For each decision, register a small contract:

1. Trigger and eligible population.
2. Exact evidence builder and completeness requirements.
3. Mutually exclusive options, including `insufficient`.
4. Pinned model/version, one action score and threshold.
5. Allowed action, unavailable fallback, baseline, error budget and stopping rule.

Keep **semantic judgment**, **evidence sufficiency** and **action policy** separately observable. Avoid another unexplained confidence × materiality gate. A deterministic evidence-availability precondition is appropriate; an additional model threshold needs its own purpose and joint evaluation. The original aggregate suppressed strong contradiction signals, while v3 still asks materiality questions that its action rule no longer consumes. ([Earlier diagnosis](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-review-astra.md:41), [current questions](/Volumes/Home/francisross/Projects/batuta/core/loop/judgment.go:282), [current aggregation](/Volumes/Home/francisross/Projects/batuta/core/loop/judgment.go:1121).)

Before calling the model, inspect whether the packet contains the decisive passage. Compare automatic retrieval with human-selected sufficient evidence on development cases. If Jev works only with manually rescued packets, the production evidence pipeline has not passed. Do not treat a byte cap as evidence sufficiency. ([Retrieval defect](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-review-astra.md:19).)

### Sample size and promotion

I propose **60 adjudicated development cases** as an initial screening budget: roughly 20 positives, 20 hard negatives and 20 mixed/insufficient cases across multiple deliveries. This is a practical stopping budget, not production validation. If the event population cannot supply meaningful positives—as with provider limits today—pause instead of manufacturing a success claim.

For an untouched validation set, size the negative stratum from the permitted false-action rate. With **zero observed errors**, the exact one-sided 95% binomial upper bound is:

`1 − 0.05^(1/n)`

That requires **59 independent negatives for <5%**, **149 for <2%**, or **299 for <1%**. These are statistical calculations, not Jev benchmark results. Correlated variants do not count as independent cases, and positive recall needs its own sample and uncertainty estimate. The earlier 80-negative calibration was a valid frozen screen, not a precise population-error estimate. ([Earlier sample-size assessment](/Volumes/Home/francisross/Projects/batuta/core/.batuta/judge-review-astra.md:84).)

Promote through **offline → shadow → visible assistance → narrowly enforced action**. Shadow preserves all baseline decisions; assistance exposes the evidence and recommendation; enforcement permits only the registered stricter action.
